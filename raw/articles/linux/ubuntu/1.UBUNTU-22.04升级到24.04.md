## 升级过程

### 1. 初始尝试

直接执行 `do-release-upgrade` 时遇到问题：
- 需要先更新当前系统的所有软件包
- 有其他 apt 进程占用锁

### 2. 清理进程

```bash
sudo kill -9 <apt进程ID>
```

### 3. 更新软件包列表

```bash
sudo apt update
```

结果：有 2089 个软件包可以升级

### 4. 升级当前系统软件包

```bash
sudo apt upgrade -y
```

过程中遇到问题：
- 进程卡在 binutils 的 preinst 脚本（debconf 交互）
- 强制终止后导致 libc6 处于 half-installed 状态

### 5. 修复依赖问题

关键步骤 - 强制安装 libc6：

```bash
sudo DEBIAN_FRONTEND=noninteractive dpkg --force-all -i /var/cache/apt/archives/libc6_2.39-0ubuntu8.7_amd64.deb
```

然后安装 libc-bin：

```bash
sudo DEBIAN_FRONTEND=noninteractive dpkg --force-all -i /var/cache/apt/archives/libc-bin_2.39-0ubuntu8.7_amd64.deb
```

配置所有软件包：

```bash
sudo DEBIAN_FRONTEND=noninteractive dpkg --configure -a
```

### 6. 完成升级

继续运行 apt upgrade：

```bash
sudo DEBIAN_FRONTEND=noninteractive apt upgrade -y
```

### 7. 清理旧软件包

```bash
sudo apt autoremove -y
```

### 8. 发行版升级（已自动完成）

由于通过 apt upgrade 已将所有软件包升级到 noble 版本，系统实际上已经完成了发行版升级，无需再运行 `do-release-upgrade`。

## 关键问题及解决方案

### 问题 1：进程占用锁

**现象**：无法获得排它锁，另一个软件包管理程序正在运行

**解决**：终止所有 apt/dpkg 相关进程

```bash
sudo kill -9 <进程ID>
```

### 问题 2：进程卡在 debconf 交互

**现象**：dpkg 解包过程中 perl/debconf frontend 进程卡住不动

**解决**：使用 `DEBIAN_FRONTEND=noninteractive` 环境变量强制非交互模式

### 问题 3：libc6 half-installed 状态

**现象**：
```
dpkg: 处理软件包 libc6:amd64 (--configure)时出错：
 现在尚不能配置软件包 libc6:amd64
 不能配置(目前状态为 half-installed )
```

**解决**：强制安装 libc6 deb 包

```bash
sudo DEBIAN_FRONTEND=noninteractive dpkg --force-all -i /var/cache/apt/archives/libc6_2.39-0ubuntu8.7_amd64.deb
```

## 经验总结

### 最佳实践

1. **升级前备份**：重要数据应提前备份
2. **使用非交互模式**：在脚本/自动化环境中使用 `DEBIAN_FRONTEND=noninteractive`
3. **耐心等待**：升级 2000+ 软件包需要时间，不要过早中断
4. **检查进程状态**：使用 `ps aux | grep apt` 检查进程是否还在运行
5. **重启系统**：升级完成后建议重启以确保所有更改生效

### 常用检查命令

```bash
# 检查当前版本
lsb_release -a

# 检查是否有进程占用锁
ps aux | grep -E 'apt|dpkg'

# 查看输出进度
tail -f <输出文件>

# 修复依赖问题
sudo apt --fix-broken install
sudo dpkg --configure -a
```

有，开源/公开可参考的 **Skill 写法资料** 还不少，而且已经有比较成体系的讲法了。你如果是想学“Skill 文档该怎么写、要包含哪些部分、有哪些坑”，下面这几类资料最有用。

## 一般要包含哪些部分

一个比较完整的 Skill，通常会有这些内容：

- `name` ：名字要短、清晰、见名知意。 [web.fly63](https://web.fly63.com/article/detial/13673)
- `description` ：写触发场景，不只是写功能摘要，最好能覆盖用户常见说法。bbs.huaweicloud+1
- 能力边界：说明“能做什么”和“不能做什么”，避免模型乱用。news.sohu+1
- 输入要求：哪些字段必填、哪些可选、用户要提供什么上下文。cloud.tencent+1
- 核心流程：分步骤写清楚怎么做，但不要把每个细节都写死。web.fly63+1
- 输出规范：结果要长什么样、格式是什么、是否要校验。juejin+1
- 参考资料 / 子文件：复杂内容放到 `references/` 或独立文档里，主文件保持简洁。gitcode.csdn+1

## 写作注意事项

最重要的是别把 Skill 写成“百科说明书”，而要写成“执行手册”。 `SKILL.md` 里应该优先放触发条件、流程、约束和检查项，背景知识尽量外移。bbs.huaweicloud+1

另外，很多教程都强调两点：

- 触发描述要具体，最好写成“当用户说什么/要什么时触发”。bbs.huaweicloud+1
- 一定要写“不做什么”，因为边界比功能描述更能控制模型行为。cloud.tencent+1

## 一个实用模板

你可以先按这个骨架写：

```
text
# SKILL 名称

## description
适用场景：……
不适用场景：……

## inputs
必填：
可选：

## workflow
1. …
2. …
3. …

## constraints
- 不要……
- 必须……

## output
输出格式：
质量要求：
```

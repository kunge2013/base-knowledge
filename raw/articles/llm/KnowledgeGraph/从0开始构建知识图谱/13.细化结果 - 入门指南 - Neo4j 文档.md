```cypher
CYPHER 25
MATCH (p:Person)
FILTER p.twitter IS NOT NULL
RETURN p.name, p.twitter
```

### 字符串和部分值

您可以使用特定的 [谓词 (predicates)](https://neo4j.ac.cn/docs/cypher-manual/current/expressions/predicates) 配合 `WHERE` ，根据存储在节点或关系中的部分值来筛选结果。

网络

#### STARTS WITH

`STARTS WITH` 运算符搜索以您指定的字符串开头的属性值，例如，以字母“M”开头的名称。

```cypher
MATCH (p:Person)
WHERE p.name STARTS WITH 'M'
RETURN p.name;
```

结果为：

| p.name |
| --- |
| `"Melissa"` |
| `“Mark”` |
| 行：2 |

#### CONTAINS

`CONTAINS` 运算符检查指定的字符串是否为属性值的一部分，例如，是否包含字母“a”。

```cypher
MATCH (p:Person)
WHERE p.name CONTAINS 'a'
RETURN p.name;
```

结果为：

| p.name |
| --- |
| `"Keanu Reeves"` |
| `"Tom Hanks"` |
| `"Diana"` |
| `"Melissa"` |
| `"Dan"` |
| `"Sally"` |
| `“Mark”` |
| 行：7 |

`ENDS_WITH` 运算符搜索属性值末尾的指定字符串，例如，以“n”结尾的 `name` 。

编程

```cypher
MATCH (p:Person)
```

| `"Dan"` |

| `"Ann"` |

您只会得到“Mark”作为结果。

#### OPTIONAL 模式

有时，即使结果不符合所有条件，您也希望从查询中返回结果。为此，可以使用 `OPTIONAL MATCH` ，它会在可选子句不匹配时返回空值 (null)。

数据管理

例如，如果您搜索名字以“J”开头且“可选地”在某家公司工作的人：

```cypher
MATCH (p:Person)
WHERE p.name STARTS WITH 'J'
OPTIONAL MATCH (p)-[:WORKS_FOR]-(other:Company)
RETURN p.name, other.name;
```

请注意，Joe 被返回了，因为他的名字以字母“J”开头，但他的公司名称为 `null` 。这是因为他没有指向 `COMPANY` 节点的 `WORKS_FOR` 关系。由于您使用了 `OPTIONAL MATCH` ，他的 `Person` 节点仍会从第一个匹配项中返回，但未找到可选匹配项，因此 `other.name` 返回 `null` 结果。

您可以查询具有多个关系的模式。例如，如果您想知道谁在同一家公司工作且也是朋友：

```cypher
MATCH (p1:Person)-[:WORKS_FOR]->(company:Company)<-[:WORKS_FOR]-(p2:Person),
(p1)-[:IS_FRIENDS_WITH]->(p2)
RETURN p1.name AS people1, p2.name AS people2, company.name AS company
```

结果为：

请注意，查询的第一行末尾有一个逗号，下一行添加了另一个 `MATCH` 模式。这允许您将不同的模式链接在一起，类似于之前使用的 [`WHERE exists(<pattern>)`](#_patterns) 。

## 限制 (Limit)

当您想要限制返回结果的数量时，可以使用 `LIMIT` 。例如，当前的示例图中共有 12 个 `Person` 节点，如果您只想检索其中的 3 个：

```cypher
MATCH (p:Person)
RETURN p
LIMIT 3
```

结果为：

| p |
| --- |
| `(:Person {born: 1964, name: "Keanu Reeves"})` |
| `(:Person {born: 1951, name: "Robert Zemeckis"})` |
| `(:Person {born: 1956, name: "Tom Hanks"})` |
| 行：3 |

由于您没有使用 [`ORDER BY`](#_order) 来指定排序方式，查询会检索添加到图中的前三个 `Person` 节点。要获取随机结果，可以在查询中添加 `ORDER BY rand()` ：

```cypher
MATCH (p:Person)
RETURN p
ORDER BY rand()
LIMIT 3
```

现在，每次运行此查询时，您都会得到 3 个随机的 `Person` 节点。

## 条目数量

如果您有一个元素列表，也可以使用 [`size()`](https://neo4j.ac.cn/docs/cypher-manual/current/functions/scalar/#functions-size) 函数返回该列表中的元素数量。

例如，如果您想知道图中每个人有多少个朋友：

```cypher
MATCH (p:Person)-[:IS_FRIENDS_WITH]-(friend:Person)
RETURN p.name, size(collect(friend.name)) AS numberOfFriends;
```

请注意， `collect()` 函数是在 `size()` 函数 **内部** 使用的。如果您不使用它（即只写 `size(friend.name)` ），函数的作用将是计算 `friend.name` 属性字符串值中包含多少个字符。因为您想知道每个人有多少个朋友，所以 `collect()` 作为聚合函数收集所有的 `friend.name` 值，而 `size()` 则返回总数量。


<table><colgroup><col> <col></colgroup><thead><tr><th>p.name</th><th>numberOfFriends</th></tr></thead><tbody><tr><td><p><code>"John"</code></p></td><td><p><code>1</code></p></td></tr><tr><td><p><code>"Jennifer"</code></p></td><td><p><code>5</code></p></td></tr><tr><td><p><code>"Joe"</code></p></td><td><p><code>2</code></p></td></tr><tr><td><p><code>"Ann"</code></p></td><td><p><code>1</code></p></td></tr></tbody><tfoot><tr><td colspan="2"><p>Rows:4</p></td></tr></tfoot></table>

这是因为 `IS_FRIENDS_WITH` 关系是有向的。

例如，Jennifer 和 Mark 通过从 Jennifer 到 Mark 的出站 `IS_FRIENDS_WITH` 关系连接（即 `(jennifer)-[:IS_FRIENDS_WITH]→(mark)` ），而不是 `(mark)-[:IS_FRIENDS_WITH]→(jennifer)` 。

数据管理

在实际应用中，Jennifer 和 Mark 是朋友这一点才是最重要的，因此关系的方向并不重要。但是，将此信息添加到图中时，关系 [必须具有方向](https://neo4j.ac.cn/docs/getting-started/cypher/#_relationship_directions) 。另一方面，查询它并不一定需要方向。

创建方向相反的新模式（即 `(mark)-[:IS_FRIENDS_WITH]→(jennifer)` ）从语法角度看并没有错，但如果方向对于回答“谁与谁是朋友？”这个问题无关紧要，这就是重复的信息。这就是为什么使用无向关系查询可以得到更准确的结果。

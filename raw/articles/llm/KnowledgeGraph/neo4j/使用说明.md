## 行业痛点与解决方案

### 电商行业面临的三大痛点

#### 痛点一：搜索不准，客户找不到想要的商品

**问题描述**：
- 客户搜索"夏天穿去上班的衣服"
- 系统只返回包含关键词"夏天"或"上班"的商品
- 结果混乱，客户翻了很多页也找不到合适的
- 客户放弃购买，离开网站

**造成的损失**：
- 转化率低
- 客户流失

#### 痛点二：营销不精准，效果差

**问题描述**：
- 30岁商务男士收到"少女风连衣裙8折"的营销邮件
- 所有客户收到一模一样的促销信息
- 客户觉得"这家店根本不懂我"
- 客户退订邮件，不再购买

**造成的损失**：
- 营销投入回报率低
- 客户反感，品牌形象受损

#### 痛点三：客服成本高，响应慢

**问题描述**：
- 客户晚上11点问"支持7天无理由退货吗？"
- 智能客服答非所问
- 人工客服要等第二天上班
- 客户不耐烦，直接投诉

**造成的损失**：
- 客服人力成本高
- 客户满意度低
- 流失潜在客户

---

### 为什么传统方案解决不了？

**传统电商系统的数据存储方式**：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   客户表    │    │   订单表    │    │   商品表    │
├─────────────┤    ├─────────────┤    ├─────────────┤
│ ID          │    │ 客户ID      │    │ 商品ID      │
│ 姓名        │◄───│ 商品ID      │    │ 名称        │
│ 年龄        │    │ 数量        │    │ 描述        │
│ 注册日期    │    │ 日期        │    │ 价格        │
└─────────────┘    └─────────────┘    └─────────────┘

问题：表和表之间是割裂的
- 系统不知道"买过西装的人通常也会买领带"
- 系统不知道"这件商品和那件商品是搭配的"
- 系统只能做简单的关键词匹配
```

**根本原因**：
- 传统数据库只存储"数据"，不存储"关系"
- 系统无法理解客户偏好、商品搭配、购买模式
- 无法做到"千人千面"的个性化服务

---

### 本项目的解决方案：GraphRAG

**核心思路**：用"知识图谱"把数据连接起来

```
知识图谱的数据存储方式：

        买了
   客户 ────► 西装
    │           │
    │ 买了      │ 搭配
    ▼           ▼
   衬衫 ◄──── 领带
        买了

优势：
- 能理解"买过A的人通常也买B"
- 能理解"这件和那件是搭配的"
- 能理解"这个客户喜欢什么风格"
```

**技术原理**：

```
┌─────────────────────────────────────────────────────────────┐
│                      用户输入                               │
│              "我想买件上班穿的衣服"                           │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│            第一步：理解语义（OpenAI）                         │
│    "上班穿" → 正式、商务、得体                               │
│    "衣服" → 衬衫、西装、外套                                 │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│             第二步：查询图谱（Neo4j）                         │
│    1. 找这个客户 → 看他买过什么                               │
│    2. 找相关商品 → 符合"商务"标签的                           │
│    3. 找搭配关系 → 什么和什么是配套的                         │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│            第三步：AI生成回答（OpenAI）                       │
│    综合以上信息，生成个性化回复                               │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      输出结果                               │
│    "根据您的购买记录，推荐这3件商务衬衫..."                   │
└─────────────────────────────────────────────────────────────┘
```

### 针对三个痛点的具体解决方案

#### 解决痛点一：搜索不准

| 传统方案 | GraphRAG方案 |
|----------|--------------|
| 关键词匹配 | 理解语义 + 个性化 |
| 返回所有包含关键词的商品 | 结合客户历史，返回最适合的商品 |

```
客户搜索: "夏天穿去上班的衣服"

传统系统:
  → 关键词匹配
  → 返回"夏天"+"上班"的商品

GraphRAG:
  → 理解语义: "夏天"+"上班" = 轻薄、正式、透气
  → 查询图谱: 这类商品有哪些？
  → 结合客户历史: 这个客户喜欢什么颜色/尺码？
  → 返回精准结果: 适合他的3件商品
```

#### 解决痛点二：营销不精准

| 传统方案 | GraphRAG方案 |
|----------|--------------|
| 千人一面 | 千人千面 |
| 群发相同内容 | 根据客户画像定制内容 |

```
客户画像（从图谱获取）:
├── 购买历史: 西装、衬衫、皮鞋
├── 风格偏好: 商务、深色系
├── 消费能力: 中高
└── 搭配需求: 缺一条领带

GraphRAG生成的邮件:
"王先生，根据您的购买记录，您有多套商务西装。
 我们新到了一款深蓝色真丝领带，与您的灰色西装非常搭配..."

而不是:
"全场8折！快来抢购！"
```

#### 解决痛点三：客服成本高

| 传统方案 | GraphRAG方案 |
|----------|--------------|
| 机械回答/等人工 | 智能回答/秒回 |
| 关键词匹配失败就转人工 | 理解语义，从知识图谱找答案 |

```
客户问: "你们支持7天无理由退货吗？"

传统智能客服:
  → 关键词匹配失败
  → 回复: "我不理解您的问题，正在为您转接人工..."

GraphRAG客服:
  → 查询知识图谱
  → 找到相关政策节点: "Policy: 7天无理由退货"
  → 结合客户信息: "您是VIP会员，享受15天退货期"
  → 生成回答: "支持！而且您是VIP，可以15天内退货..."
```

## 项目简介

### 什么是 GraphRAG？

GraphRAG（Graph-based Retrieval Augmented Generation）是一种基于图的检索增强生成技术，它结合了：
- **向量相似度搜索**：基于语义的文本匹配
- **图遍历**：利用数据之间的关系进行上下文检索

### 业务场景

本项目演示了 GraphRAG 在零售/电商客户旅程中的四个关键应用场景：

| 场景 | 解决的痛点 | 业务目标 |
|------|------------|----------|
| **Discovery（发现）** | 营销不精准 | 提高点击率 |
| **Search（搜索）** | 搜索不准 | 提高转化率 |
| **Recommendations（推荐）** | 推荐不精准 | 提高客单价 |
| **Support（支持）** | 客服成本高 | 降低服务成本 |

### 数据来源

项目使用 [H&M 个性化时尚推荐数据集](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data)，包含真实的客户购买数据和丰富的产品信息（名称、类型、描述、部门等）。

## 数据初始化

数据初始化包含两个部分：**产品图谱** 和 **客服知识图谱**。

### 前置条件

数据加载需要以下条件之一：
- [Neo4j AuraDS 实例](https://neo4j.com/docs/aura/aurads/create-instance/)（推荐）
- Neo4j Desktop / Sandbox / Server / Docker（需安装 [Graph Data Science](https://neo4j.com/docs/graph-data-science/current/installation/)）

### 第一部分：产品图谱加载

产品图谱为 Discovery、Search 和 Recommendations 页面提供数据支持。

#### 数据模型

```
(Customer)-[:PURCHASED]->(Article)-[:VARIANT_OF]->(Product)
```

| 节点类型 | 属性 | 说明 |
|----------|------|------|
| `Customer` | customerId | 客户节点 |
| `Article` | graphEmbedding | 商品条目（含图嵌入向量） |
| `Product` | text, textEmbedding | 产品节点（含文本和文本嵌入向量） |

#### 向量索引

- `product_text_embeddings`：产品文本嵌入索引
- `article_graph_embeddings`：商品图嵌入索引

#### 加载步骤

1. **准备数据文件**

   从 [Kaggle 竞赛页面](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data) 下载以下文件：
   - `customers.csv`
   - `articles.csv`
   - `transactions.csv`

2. **使用 Notebooks 加载数据**

   项目提供了两个数据加载 Notebook：

   | Notebook | 用途 |
   |----------|------|
   | [load-data/hm-data.ipynb](https://github.com/neo4j-product-examples/graphrag-examples/blob/main/patterns-app/load-data/hm-data.ipynb) | 加载 H&M 数据集 |
   | `explore-retrievers-and-chains.ipynb` | 探索检索器和链 |

   **注意**：由于 Notebook 文件未包含在本项目中，请从 GitHub 仓库获取。

3. **运行图算法**

   加载数据后，需要运行图算法生成嵌入向量：

   ```cypher
   // 运行 Node2Vec 算法生成图嵌入
   CALL gds.node2vec.write('article-similarity', {
     embeddingDimension: 128,
     writeProperty: 'graphEmbedding'
   })
   ```

### 第二部分：客服知识图谱加载

客服知识图谱为 Support 页面提供数据支持，基于 PDF 文档构建。

#### 数据模型

客服图谱使用以下节点标签（定义在 `support-node-labels.txt` 中）：

| 节点标签 | 说明 |
|----------|------|
| `Concept` | 概念 |
| `Group` | 分组 |
| `Item` | 物品 |
| `Material` | 材料 |
| `Membership` | 会员 |
| `Organization` | 组织 |
| `Person` | 人员 |
| `Place` | 地点 |
| `Policy` | 政策 |
| `Process` | 流程 |
| `Service` | 服务 |
| `ShippingOption` | 配送选项 |

#### 加载步骤

使用 [LLM Graph Builder](https://neo4j.com/labs/genai-ecosystem/llm-graph-builder/) 构建客服知识图谱：

1. **打开 LLM Graph Builder**

   访问在线应用：https://llm-graph-builder.neo4jlabs.com/

2. **连接数据库**

   连接到与产品图谱相同的 Neo4j 数据库。

3. **上传 PDF 文档**

   将 [客服 FAQ PDF 文档](https://drive.google.com/file/d/1Ec1vaKlcySmF24JGJqhHfRwvEBdcZ7EZ/view) 拖放到左上角的上传区域。

   > 该 PDF 包含从 H&M 网站抓取的客服和 FAQ 信息，部分链接和品牌名称已替换为虚拟值。

4. **配置图 Schema**

   a. 点击 "Graph Enhancement" 按钮，然后点击 "Get Schema From Text" 按钮

   b. 复制 `support-node-labels.txt` 文件的内容并粘贴到输入框：

   ```
   Concept
   Group
   Item
   Material
   Membership
   Organization
   Person
   Place
   Policy
   Process
   Service
   ShippingOption
   ```

   c. 勾选 "text is schema description" 复选框

   d. 点击 "Analyze text to extract graph schema" 按钮

   e. 完成后，你应该看到提取的 Schema

5. **生成图谱**

   点击 "Generate Graph" 按钮并等待完成。

6. **预览图谱**

   点击 "Preview Graph" 查看生成的知识图谱。

### 数据加载验证

加载完成后，可在 Neo4j Browser 中执行以下查询验证：

```cypher

```

### 向量索引操作

#### 创建向量索引

```cypher
// 为产品文本嵌入创建向量索引
CREATE VECTOR INDEX product_text_embeddings IF NOT EXISTS
FOR (n:Product)
ON n.textEmbedding
OPTIONS {indexConfig: {
  `vector.dimensions`: 1536,
  `vector.similarity_function`: 'cosine'
}};

// 为商品图嵌入创建向量索引
CREATE VECTOR INDEX article_graph_embeddings IF NOT EXISTS
FOR (n:Article)
ON n.graphEmbedding
OPTIONS {indexConfig: {
  `vector.dimensions`: 128,
  `vector.similarity_function`: 'cosine'
}};

// 为客服知识图谱创建向量索引
CREATE VECTOR INDEX vector IF NOT EXISTS
FOR (n:Document)
ON n.textEmbedding
OPTIONS {indexConfig: {
  `vector.dimensions`: 384,
  `vector.similarity_function`: 'cosine'
}};
```

#### 执行向量搜索

```cypher
// 基于文本嵌入的语义搜索
CALL db.index.vector.queryNodes('product_text_embeddings', 5, $queryEmbedding)
YIELD node, score
RETURN node.name AS product, node.description AS description, score
ORDER BY score DESC;

// 基于图嵌入的相似商品搜索
CALL db.index.vector.queryNodes('article_graph_embeddings', 5, $queryEmbedding)
YIELD node, score
RETURN node.articleName AS article, score
ORDER BY score DESC;
```

### 图算法操作

#### Node2Vec 图嵌入

```cypher
// 创建商品相似度图投影
CALL gds.graph.project('article-similarity', 'Article', 'VARIANT_OF');

// 运行 Node2Vec 算法
CALL gds.node2vec.write('article-similarity', {
  embeddingDimension: 128,
  iterationCount: 10,
  walkLength: 80,
  writesToNodeProperties: 'graphEmbedding'
});
```

### 数据库维护

```cypher
// 清空数据库（谨慎使用）
MATCH (n) DETACH DELETE n;

// 删除特定标签的节点
MATCH (n:Product) DETACH DELETE n;

// 重建索引
CALL db.index.fulltext.drop('product_text_embeddings');
```

## 应用功能详解

### Discovery（发现）- 个性化邮件生成

**解决的痛点**：营销不精准

**功能**：根据客户购买历史生成个性化营销邮件

**输入参数**：
- Customer ID：客户 ID
- Product Code：产品代码（可选）

**输出**：
- 个性化营销邮件内容

**技术实现**：
- 检索客户购买历史
- 获取相关产品信息
- 使用 GPT-4o 生成个性化邮件

### Search（搜索）- 语义搜索

**解决的痛点**：搜索不准

**功能**：基于自然语言的产品语义搜索

**输入参数**：
- Query：搜索查询文本

**输出**：
- 匹配的产品列表（按相关性排序）

**技术实现**：
- 使用 text-embedding-ada-002 生成查询嵌入
- 在 `product_text_embeddings` 索引中执行向量搜索
- 结合图遍历获取相关产品

### Recommendations（推荐）- 产品推荐

**解决的痛点**：推荐不精准

**功能**：基于客户行为和图结构的个性化推荐

**输入参数**：
- Customer ID：客户 ID
- Query：查询文本

**输出**：
- 推荐产品列表

**技术实现**：
- 结合向量相似度和图结构
- 考虑客户购买历史和商品变体关系
- 与纯向量搜索进行对比展示

### Support（支持）- 客服问答

**解决的痛点**：客服成本高

**功能**：基于知识图谱的客服问答

**输入参数**：
- Question：客户问题

**输出**：
- 基于知识图谱的回答

**技术实现**：
- 使用 all-MiniLM-L6-v2 生成本地嵌入
- 在客服知识图谱中检索相关信息
- 使用 LLM 生成回答

## 常见问题

### Q1: 启动时遇到 "Connection refused" 错误

**解决方案**：
1. 确保 Docker 服务正在运行
2. 检查 Neo4j 数据库连接配置是否正确
3. 验证 OpenAI API Key 是否有效

### Q2: 搜索结果为空

**解决方案**：
1. 确认数据已成功加载到 Neo4j
2. 检查向量索引是否已创建：`SHOW INDEXES WHERE type = 'VECTOR';`
3. 验证嵌入维度配置是否正确

### Q3: 邮件生成内容不准确

**解决方案**：
1. 检查客户购买历史数据
2. 确认产品信息完整
3. 调整 Prompt 模板（位于 `api/packages/neo4j_chains/email_chain.py`）

### Q4: Docker 构建失败

**解决方案**：
```bash
# 清理缓存重新构建
docker-compose build --no-cache

# 或删除所有容器和镜像后重建
docker-compose down --rmi all
docker-compose up --build
```

### Q5: 如何在生产环境部署？

**建议**：
1. 使用 Neo4j AuraDS 托管服务
2. 将 API 部署到云服务商（AWS/GCP/Azure）
3. 使用负载均衡器处理请求
4. 配置环境变量管理敏感信息
5. 启用日志和监控

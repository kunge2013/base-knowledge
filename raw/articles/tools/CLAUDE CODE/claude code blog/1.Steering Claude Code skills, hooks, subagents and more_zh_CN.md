Claude 的设计理念就是为了适应你的工作方式，而且在 Claude Code 中你可以对其进行自定义。

有七种方法可以指示 Claude 的行为：CLAUDE.md 文件、规则、 [**技能**](https://code.claude.com/docs/en/skills) 、 [**子代理**](https://code.claude.com/docs/en/sub-agents) 、 [**钩子**](https://code.claude.com/docs/en/hooks-guide) 、输出样式以及附加系统提示符。

每种方法控制：

- 当一条指令加载到上下文中时；
- 这种现象是否会在长时间会话中持续存在（压缩行为）；以及
- 它拥有多大的权威性。

下表简要概述了每种方法的主要区别，而该帖子则提供了更多细节和决策框架，以确定您的每个 Claude 指令属于哪个类别。

| 方法             | 加载完毕                                | 压实行为                              | 背景成本                                 | 何时使用                                                  |
| -------------- | ----------------------------------- | --------------------------------- | ------------------------------------ | ----------------------------------------------------- |
| CLAUDE.md（根目录） | 会话开始；在整个会话期间保持上下文一致                 | 已缓存。读取一次并缓存到会话期间；缓存清除后，压缩完成后重新读取。 | 高。无论是否相关，每条线都需要代币。                   | 构建命令、目录布局、单体仓库结构、编码规范、团队规范                            |
| CLAUDE.md（子目录） | 按需执行，当 Claude 读取该子目录下的文件时           | 丢失，直到再次访问该子目录为止。                  | 低。仅在正在处理相关子目录时才消耗上下文。                | 子目录特有的约定                                              |
| 规则             | 会话开始（用户级规则）或仅当访问匹配的文件时（路径范围）        | 压实后重新注入                           | 中等。始终开启，除非是路径作用域。                    | 具体约束或约定（例如，所有 API 处理程序都必须使用 Zod 验证输入）                 |
| 技能             | 会话开始时的名称和描述；技能发动时的全身负荷              | 重新启用的技能将纳入共享预算；最早的技能优先淘汰。         | 低。仅在发动时才会产生全身负荷；受所发动技能共享的代币预算限制。     | 流程工作流程（部署或发布清单）                                       |
| 次级代理商          | 会话开始时显示名称、描述和工具列表；仅当通过代理工具调用时才加载主体。 | 只有最终消息（摘要加元数据）会返回到主会话。            | 低成本。在主上下文中调用前成本为零；在自身独立的上下文窗口中运行。    | 并行运行的工作或应该独立运行且只返回摘要的辅助任务（深度搜索、日志分析、依赖关系审计）           |
| 钩子             | 生命周期事件中的火灾                          | 完全绕过压实                            | 低。配置信息存在于主上下文之外；可能会返回一些输出（例如，阻塞性错误）。 | 确定性自动化：运行代码检查器，完成后发布到 Slack，阻止命令，在 PreCompact 上备份聊天记录 |
| 输出样式           | 会话开始；注入到系统提示符中                      | 从未压实                              | 高优先级。占用上下文窗口，但会覆盖默认系统提示符。            | 角色发生重大变化（从代码助理到普通助理）                                  |
| 附加系统提示         | 会话开始；作为 CLI 标志传递                    | 从未压缩；仅适用于该次调用                     | 中等。会话中首次请求后缓存。                       | 语气、回复长度、格式偏好                                          |

## 七种传达指令的方法

### CLAUDE.md 文件

CLAUDE.md 是项目根目录下的一个 Markdown 文件。它会在会话开始时加载到上下文中，并在整个会话期间保持加载状态。

构建命令、目录布局、单体仓库结构、编码约定和团队规范都自然地融入其中。

有两种类型，它们的加载方式不同：

- **始终加载** ：第一种类型是根目录下的 CLAUDE.md 文件，它可能位于共享仓库中，也可能保存在本地，用于设置您特定于项目的个人偏好。所有这些文件都会在会话开始时加载，并且在长时间会话中不会丢失或损坏。当 Claude Code 压缩对话时，它会重新读取这些文件。
- **按需加载：** CLAUDE.md 文件位于您初始化会话的文件夹下的子目录中。例如， `app/api/CLAUDE.md` 当 Claude 读取该子目录中的文件时，该文件才会加载 ` app/api` ，而不是在会话开始时加载。它与路径作用域规则的压缩行为相同：只有在再次访问该子目录时才会被删除。
![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a340f852d1f938ab8675599_65a737a9.png)

当 Claude 读取当前目录下的文件时，会加载当前工作目录 (cwd) 下的所有子目录 CLAUDE.md 文件。

在共享代码库中，CLAUDE.md 文件的增长方式与任何无人认领的配置文件一样：每个团队都会添加自己的指令，而且没有任何内容会被删除。规模越大，成本就越高。

对于代码库中每位工程师的每个会话，无论其任务是否相关，每一行代码都会加载到会话中。这会消耗令牌，并降低对真正重要指令的遵循度。随着文件的增长，应将团队特定的约定推送到路径作用域的规则中，并将流程推送到技能中，使其仅在相关时加载。

**提示：** CLAUDE.md 文件应控制在 200 行以内，指定负责人，并像审查代码一样审查其更改。您可以将此文件视为 Claude 的代码库概览，或者指向其他文件的索引，以便 Claude 在需要时查找更多信息。

在单体仓库中，为每个团队的目录添加一个子目录 CLAUDE.md，这样团队就只会加载自己的约定，开发者可以使用 claudeMdExcludes 设置来跳过他们从不接触的团队的代码文件。

对于必须适用于组织中每个存储库的标准（安全策略、合规性要求），可以通过 MDM 或配置管理将集中管理的 CLAUDE.md 部署到开发人员的机器上，并且不能通过个别设置将其排除在外。

有关设置 CLAUDE.md 的更多信息，请参阅我们的博客文章“ [CLAUDE.md 文件：为您的代码库自定义 Claude 代码”](https://claude.com/blog/using-claude-md-files) 。

### 规则

[**规则**](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/) 是 Markdown 文件，`.claude/rules/ ` 它为 Claude 提供特定的约束或约定。

无作用域规则的行为类似于 CLAUDE.md，它们总是在会话启动时加载，并在压缩时重新注入。这可能会浪费令牌，因为即使上下文与当前任务无关，它们也会加载上下文。

路径作用域规则允许您通过添加一个 `paths` 控制何时加载规则指令的字段，仅在规则指令相关时才加载它们。

例如：一条作用域限定的规则 `src/api/**` 在仅读取文档的会话期间不会生效。它只会在 Claude 读取该目录中的文件时才会加载 `src/api/ ` 。

这就是它的样子：

```yaml
---
paths:
  - "src/api/**"
  - "**/*.handler.ts"
---
All API handlers must validate input with Zod before processing.
```

**提示** ：像“迁移仅追加”这样的文件特定约束最好作为 **规则** 放在路径的 frontmatter 部分。当指令涉及横切关注点或出现在代码库多个（但并非所有）位置的文件时，应使用路径范围的规则，而不是嵌套的 CLAUDE.md 文件。

### 技能

[**技能**](https://code.claude.com/docs/en/skills) 以文件夹的形式存在`.claude/skills/` ，文件夹内包含指令、脚本和资源，由 Claude 动态加载。每个技能都有一个 `SKILL.md` 文件，其中包含名称、描述和正文。

会话开始时仅加载名称和描述；当 Claude 通过斜杠命令 (/code-review) 或通过自动匹配任务调用技能时，才会加载完整的身体模型。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a340f852d1f938ab867559f_2199ed03.png)

技能通过系统提示触发。

例如， `/code-review` 这是一个内置技能，它可以检查你当前的差异并报告结果，而无需编辑文件。该技能定义了操作手册，因此每次调用 Claude 时，它都会遵循相同的结构化方法。

在压缩过程中，Claude Code 会重新注入已调用的技能，但总预算不会超过设定值。如果在一次会话中调用了许多技能，则最早调用的技能会首先被移除。

**提示：** 程序性说明，如部署工作流程、发布清单或审查流程，应放在技能中，而不是放在 CLAUDE.md 中。

Claude Code 自带一些技能，但你也可以编写自己的自定义技能。我们的 [Claude 技能构建完整指南](https://claude.com/blog/complete-guide-to-building-skills-for-claude) 将向你展示如何操作。

### 次级代理商

[**子代理**](https://code.claude.com/docs/en/sub-agents) 是 Markdown 文件，用于`.claude/agents/ ` 定义执行特定辅助任务的独立助手。每个文件都使用 YAML 前置元数据（名称、描述以及用于模型和工具访问的可选字段），后跟主体部分，该主体部分将成为该子代理的系统提示符。

子代理与技能类似，名称、描述和工具列表会在会话开始时加载，但代理主体内的更大上下文不会自动调用。Claude 通过代理工具调用它们，并传入一个提示字符串。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a340f852d1f938ab86755a2_914c1942.png)

Claude Code 的上下文窗口包含了 Claude 了解的关于您会话的所有信息。 此处的交互式时间轴 会逐步展示加载的内容及其加载时间。

不仅子代理体内的较大教学上下文不会自动调用，而且它根本不会进入父对话。

然后，子代理会在它自己的全新上下文窗口中运行，唯一返回到主会话的是子代理的最终消息（通常是许多子任务的聚合结果）以及元数据。

这种模式具有可扩展性：子代理最多可以嵌套五层， [动态工作流](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code) 可以协调数十到数百个后台代理，而无需您指定子代理架构的每个细节。编排计划和中间结果存储在脚本变量中，而不是 Claude 的上下文窗口中，这使得扩展能够在不损失教学质量的前提下实现。

**提示：** 这种隔离性是选择子代理而非技能的主要原因之一。当诸如深度搜索、日志分析或依赖关系审计之类的辅助任务会用你以后不会再引用的中间结果使主线程变得混乱时，请使用子代理。当你希望流程在主线程中执行，以便你可以查看和控制每个步骤时，请使用技能。

### 钩子

[**钩子**](https://code.claude.com/docs/en/hooks-guide) [是用户定义的命令、HTTP 端点或 LLM 提示，通过在 Claude 生命周期中的特定事件](https://code.claude.com/docs/en/hooks#hook-lifecycle) （例如文件编辑、工具调用或会话启动） 触发，来提供对 Claude 行为的更确定性的控制

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a340f852d1f938ab867559c_e782277c.png)

Claude Code 会话中钩子可以触发的事件图。

`settings.json` 您可以在托管策略设置或技能/代理前端 中注册钩子。

钩子有几种类型：command、HTTP、mcp\_tool、prompt 和 agent。所有钩子都是确定性触发的。前三种钩子确定性地执行，而后两种钩子（prompt 和 agent）则使用 Claude 的判断而非一组规则来决定输出。

钩子函数的上下文开销很低，因为配置或指令位于主上下文窗口之外。根据钩子函数的类型，程序会运行处理程序（命令、HTTP、mcp\_tool）或在单独的窗口（提示、代理）中进行模型调用。

某些钩子函数的输出可能会保存到主上下文窗口中。例如，阻塞钩子函数的标准错误输出会保存在上下文窗口中，以便 Claude 知道调用被拒绝的原因。

但大多数钩子函数不会将输出保存到主窗口，除非配置明确允许。如果您在使用该 `PreCompact` 事件进行压缩之前，将聊天记录备份到另一个文件以供后续参考，那么 Claude 将无法确定哪个文件保存了聊天记录。

这使得这些钩子类型与 CLAUDE.md、规则和技能有着本质区别。您可以在我们关于 [**如何配置钩子的**](https://claude.com/blog/how-to-configure-hooks) 文章中了解更多信息。

**提示：** 对于任何需要确定性执行的操作，例如编辑后运行代码检查、代码完成后发布到 Slack 或在特定命令执行前阻止它们，都可以使用钩子。 `PreToolUse` 钩子可以检查任何工具调用，并以退出代码 2 拒绝该调用。

它们具有较低的上下文成本，因为它们是程序运行的代码，而不是加载到上下文中的 Claude 指令。

### 输出样式

[**输出样式**](https://code.claude.com/docs/en/output-styles) 文件`.claude/output-styles/` 会将指令注入到系统提示符中。它们不会被压缩，会在每个会话开始时加载，并在会话中的第一次请求后被缓存，这意味着它们会带来一定的上下文开销。

由于输出样式位于系统提示符中，因此它们在我们目前所介绍的所有方法中具有最高的指令遵循权重，应该谨慎使用。

**输出样式的更改将替换默认输出样式** （除非您在样式的前言中设置 keep-coding-instructions: true）。

在 Claude 代码中，这将删除用于告知 Claude 它正在帮助用户完成软件工程任务的指令，并包含其他关键的默认指令，例如：

- 如何界定变更范围；
- 何时添加或省略代码注释；
- 如何应对安全问题；以及
- 养成良好的验证习惯，例如在宣布工作完成之前运行测试。

默认情况下，自定义输出样式会丢弃所有这些内容，Claude Code 更像是一个通用助手，而不是一个软件工程师助手。

**提示** ：在编写自定义输出样式之前，请先查看内置样式。 **“主动式** ” 、 **“解释式”** 和 **“学习式** ”涵盖了最常见的需求（自主性、教学模式、协作编码），无需您维护样式文件。

### 附加系统提示

除了修改输出样式之外，还可以使用追加 `append-system-prompt` 标志。修改输出样式文件可能会对 Claude 的行为造成意想不到的重大改变，而追加标志只会对原始系统提示符进行添加。它不会改变 Claude 的角色；它只是在其默认角色上添加指令。

它也是在调用时传递的，并且仅适用于该次调用，而不是作为文件跨会话持久保存。

与其他传递指令的方法相比，附加系统提示符会增加上下文开销。虽然提示符缓存会在会话中的首次请求后降低这种开销，但它会增加输入标记的数量。指示 Claude 使用更详细或更长的格式也会增加输出标记的数量。

**提示：** 附加系统提示最适合添加特定的编码规范、输出格式或领域特定知识。但请注意，附加系统提示对提高代码遵循度的收益会递减。通常情况下，您使用此方法提供的指令越多，Claude 就越不会严格遵循，尤其是在指令之间存在矛盾的情况下。

## Claude Code 自定义快速技巧

如果您发现自己正在执行以下任何操作，您可能需要考虑将说明发布在其他位置：

**CLAUDE.md 中有“每次 X 发生时，始终执行 Y”的规则。** 如果该行为需要可靠地执行，例如每次编辑后运行 pretier 或完成后发布到 Slack，则应使用钩子函数 `settings.json` 。选择运行格式化程序的模型与自动运行的格式化程序是不同的。

**CLAUDE.md 中** 有一条“切勿这样做”的警告。当某些事情绝对不能发生时，指令并非最佳选择。Claude 大多数情况下会遵循指令，但在压力下、长时间会话中、情况不明朗时，或者由于任务过程中访问的文件中包含提示信息，模型可能无法遵循提示规则。真正的防护措施必须是确定性的，而强制执行方法是 [钩子](https://code.claude.com/docs/en/hooks) 和 [权限](https://code.claude.com/docs/en/permissions) 。 `PreToolUse` 钩子可以检查调用并以代码 2 退出以阻止它。 [**托管设置**](https://code.claude.com/docs/en/settings#managed-settings) 更进一步：它们由管理员部署，无法被用户的本地配置覆盖，并且是强制执行确定性、组织范围防护措施的唯一方法。

**CLAUDE.md 中包含一个 30 行的操作步骤。** 这些步骤应该放在技能部分。CLAUDE.md 用于存放 Claude 需要始终遵循的事实：构建命令、单体仓库布局、团队约定等等。部署运行手册或安全审查清单应该放在另一个文件中`.claude/skills/` ，该文件的内容仅在被调用时加载。

**一条不包含路径的 API 特定规则。** 如果一条规则仅适用于某个 API `src/api/**` ，使用 \`@scope\` 限定其 `paths:`作用域可以避免在不相关的操作中出现该规则。未限定作用域的规则在机制上等同于将内容放在 CLAUDE.md 文件中：始终加载，始终消耗令牌。

**将个人偏好设置写入项目级 CLAUDE.md 文件。** 所有基于文件的方法在每次 Claude Code 会话中都会加载对应的用户级文件，无论您在哪个代码库中。使用本地文件记录个人偏好设置（始终使用语义化的提交信息）。将项目级文件用于团队通用但特定于特定代码库的偏好设置。

## 总结

本文系统介绍了 Claude Code 的 7 种指令控制方法，核心观点是：**根据场景选择合适的方式，而非把所有指令堆在 CLAUDE.md 中**。

| #   | 方法                  | 加载时机            | 上下文成本 | 适用场景                         |
| --- | ------------------- | --------------- | ----- | ---------------------------- |
| 1   | **CLAUDE.md（根目录）**  | 会话开始，始终加载       | 高     | 构建命令、目录结构、编码规范等全局约定          |
| 2   | **CLAUDE.md（子目录）**  | 访问子目录时按需加载      | 低     | 子目录特有的约定                     |
| 3   | **规则（Rules）**       | 会话开始或访问匹配文件时    | 中     | 具体约束（如 API 必须用 Zod 验证输入）     |
| 4   | **技能（Skills）**      | 手动调用或自动匹配时加载    | 低     | 流程性工作流（部署清单、发布流程、代码审查）       |
| 5   | **子代理（Sub-agents）** | 通过 Task 工具调用时加载 | 极低    | 并行任务、独立辅助任务（深度搜索、日志分析）       |
| 6   | **钩子（Hooks）**       | 生命周期事件触发        | 低     | 确定性自动化（代码检查、Slack 通知、阻止危险命令） |
| 7   | **输出样式 / 附加系统提示**   | 会话开始            | 高     | 角色切换、语气/格式偏好                 |

**关键决策原则：**
- **CLAUDE.md 中有"每次 X 发生时，始终执行 Y"** → 改用 **钩子**
- **CLAUDE.md 中有"切勿这样做"** → 改用 **钩子 + 权限**（确定性防护）
- **CLAUDE.md 中有 30 行操作步骤** → 改用 **技能**
- **规则仅适用于特定路径** → 使用 **路径作用域规则**（`paths:` frontmatter）
- **个人偏好** → 使用 **用户级文件**，而非项目级 CLAUDE.md

**CLAUDE.md 最佳实践：** 控制在 200 行以内，指定负责人，像审查代码一样审查其变更。可用作代码概览或索引，指向详细信息。

# Claude Code Subagent 使用场景与 Demo

## 核心设计哲学

Subagent 的本质是 **上下文隔离 + 专业化分工**。当某个副任务会产生大量输出、需要特殊权限约束、或者可以独立并行时，就该用 subagent。

---

## 场景一：大量输出隔离（最经典用法）

**问题**：运行测试套件、读取大型日志、搜索整个代码库会产生成百上千行输出，全部灌入主对话会浪费 context window。

**使用方式**：
```
用 subagent 跑测试套件，只汇报失败的测试和错误信息
```

Claude 会自动委派给 Explore 或 general-purpose subagent，测试结果留在 subagent 的 context 里，主对话只收到摘要。

**效果对比**：
- 不用 subagent：5000 行测试日志全部进入主对话 context
- 使用 subagent：主对话 context 只增加 ~200 字的摘要

---

## 场景二：并行独立研究

**问题**：需要同时探索多个互不依赖的模块。

**使用方式**：
```
并行研究 authentication、database 和 API 模块，用不同的 subagent 各自探索
```

三个 subagent 同时工作，最后 Claude 综合结果。适用于互不依赖的调研任务。

---

## 场景三：代码审查（只读、受限工具）

**问题**：需要审查代码但不想让审查者修改文件。

**创建文件**：`~/.claude/agents/code-reviewer.md`

```markdown
---
name: code-reviewer
description: Expert code review specialist. Proactively reviews code for quality, security, and maintainability. Use immediately after writing or modifying code.
tools: Read, Grep, Glob, Bash
model: inherit
---

You are a senior code reviewer ensuring high standards of code quality and security.

When invoked:
1. Run git diff to see recent changes
2. Focus on modified files
3. Begin review immediately

Review checklist:
- Code is clear and readable
- No duplicated code
- Proper error handling
- No exposed secrets or API keys
- Input validation implemented
- Good test coverage

Provide feedback organized by priority:
- Critical issues (must fix)
- Warnings (should fix)
- Suggestions (consider improving)
```

**关键点**：`tools` 只列了只读工具，没有 Write 和 Edit，审查者只能查看不能修改。

**使用方式**：
- 自然语言：`让 code-reviewer 看看 auth 模块的改动`
- @-mention：`@"code-reviewer (agent)" look at my changes`

---

## 场景四：Bug 修复（可读写、完整工具）

**问题**：需要诊断问题并直接修改代码修复。

**创建文件**：`.claude/agents/debugger.md`

```markdown
---
name: debugger
description: Debugging specialist for errors, test failures, and unexpected behavior. Use proactively when encountering any issues.
tools: Read, Edit, Bash, Grep, Glob
---

You are an expert debugger specializing in root cause analysis.

When invoked:
1. Capture error message and stack trace
2. Identify reproduction steps
3. Isolate the failure location
4. Implement minimal fix
5. Verify solution works

Focus on fixing the underlying issue, not the symptoms.
```

**关键区别**：相比 code-reviewer，多了 `Edit` 工具，可以修改文件。

---

## 场景五：只读数据库查询（Hook 条件约束）

**问题**：需要让 subagent 查数据库，但严格禁止写操作。

**创建文件**：`.claude/agents/db-reader.md`

```markdown
---
name: db-reader
description: Execute read-only database queries. Use when analyzing data or generating reports.
tools: Bash
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate-readonly-query.sh"
---

You are a database analyst with read-only access.
```

**创建验证脚本**：`./scripts/validate-readonly-query.sh`

```bash
#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

if echo "$COMMAND" | grep -iE '\b(INSERT|UPDATE|DELETE|DROP|CREATE|ALTER)\b' > /dev/null; then
  echo "Blocked: Only SELECT queries allowed" >&2
  exit 2
fi
exit 0
```

**工作原理**：
1. subagent 每次执行 Bash 命令前，Hook 脚本先运行
2. 脚本检查命令是否包含 SQL 写操作
3. 如果包含写操作，`exit 2` 阻止执行并返回错误
4. 如果是 SELECT 查询，`exit 0` 放行

## 场景六：跨项目持久化记忆

**问题**：希望 subagent 记住项目中的架构决策、代码规范、常见问题，跨会话生效。

**创建文件**：`.claude/agents/code-reviewer.md`

```markdown
---
name: code-reviewer
description: Reviews code for quality and best practices
memory: project
---

You are a code reviewer. Before reviewing, check your memory for
known patterns and conventions. After reviewing, update your memory
with new patterns you discover.
```

**memory 字段三种取值**：

| 值 | 存储位置 | 适用场景 |
|---|---|---|
| `project` | `.claude/agent-memory/code-reviewer/` | 项目专属知识，可通过 git 共享 |
| `user` | `~/.claude/agent-memory/code-reviewer/` | 跨项目通用知识 |
| `local` | `.claude/agent-memory-local/code-reviewer/` | 项目专属但不进版本控制 |

**效果**：subagent 在 `.claude/agent-memory/code-reviewer/MEMORY.md` 中积累知识，每次会话启动时自动读取。

## 场景七：成本控制（路由到 Haiku）

**问题**：简单的代码搜索、文件查找不需要 Sonnet/Opus，用 Haiku 更便宜更快。

**创建文件**：`~/.claude/agents/file-finder.md`

```markdown
---
name: file-finder
description: Fast file and code search. Use for locating files, finding function definitions, and understanding file structure.
tools: Read, Grep, Glob
model: haiku
---

You are a fast code search specialist. Locate files and code patterns quickly.
```

**成本对比**（以 Claude Code 定价为例）：

| 模型 | 适用场景 | 相对成本 |
|---|---|---|
| Haiku | 文件搜索、简单查询 | 1x |
| Sonnet | 主对话、复杂推理 | ~3x |
| Opus | 深度架构分析 | ~8x |

对于搜索类任务，Haiku 能力足够，成本仅为 Sonnet 的 1/3。

---

## 场景八：Chain 链式工作流

**问题**：多步骤流程，前一个 subagent 的结果是后一个的输入。

**使用方式**：
```
先用 code-reviewer 找出性能问题，然后用 optimizer 修复它们
```

Claude 会依次调用两个 subagent：
1. code-reviewer 执行审查，返回问题列表
2. Claude 将问题列表传递给 optimizer
3. optimizer 根据问题列表实施修复

---

## 场景九：Fork 模式（继承完整上下文）

**问题**：需要让 subagent 看到当前完整对话上下文，而不是从头解释。

**启用方式**：设置环境变量 `CLAUDE_CODE_FORK_SUBAGENT=1`

**使用方式**：
```
/fork 帮我为刚才的 parser 改动写单元测试
```

**Fork vs 普通 Subagent 对比**：

| 维度 | Fork | 普通 Subagent |
|---|---|---|
| 上下文 | 完整对话历史 | 只有任务 prompt |
| 系统 prompt | 与主会话相同 | 来自 subagent 定义 |
| 模型 | 与主会话相同 | 来自 subagent 的 model 字段 |
| Prompt 缓存 | 与主会话共享 | 独立缓存 |
| 适用场景 | 需要完整上下文时 | 独立任务 |

---

## 场景十：CLI 临时 Subagent（不写文件）

**问题**：快速测试一个 subagent 想法，不想创建文件。

**使用方式**：
```bash
claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer. Focus on code quality, security, and best practices.",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  },
  "debugger": {
    "description": "Debugging specialist for errors and test failures.",
    "prompt": "You are an expert debugger. Analyze errors, identify root causes, and provide fixes."
  }
}'
```

特点：仅当前会话有效，不保存到磁盘，适合快速测试或自动化脚本。

---

## 场景十一：项目专属 Subagent（团队共享）

**问题**：团队需要统一的代码审查标准，所有成员共享同一个 subagent 配置。

**创建文件**：`{项目根目录}/.claude/agents/project-reviewer.md`

```markdown
---
name: project-reviewer
description: Reviews code following our team specific conventions. Use after each PR.
tools: Read, Grep, Glob, Bash
memory: project
---

You are reviewing code against our team conventions:
1. All API endpoints must use the standard error envelope
2. Database queries must use the repository pattern
3. Auth checks must use the @RequireAuth decorator
4. All public functions must have JSDoc comments

Check these conventions in addition to general code quality.
```

**特点**：
- 放在项目的 `.claude/agents/` 目录
- 随 git 提交，团队成员自动获得
- 配合 `memory: project` 积累项目知识

## 决策流程图

```
需要子任务吗？
├── 输出量大？          → 用 subagent（隔离 context）
├── 需要工具限制？       → 用 custom subagent（控制 tools）
├── 可以并行？           → 多个 subagent 并行
├── 需要持久化记忆？     → 设置 memory 字段
├── 需要完整上下文？     → 用 Fork 模式（/fork）
├── 简单问答？           → 用 /btw（不需要 subagent）
└── 需要频繁对话迭代？   → 留在主对话
```

## 三种调用方式对比

| 方式        | 语法                             | 保证执行？          | 适用场景   |
| --------- | ------------------------------ | -------------- | ------ |
| 自然语言      | `用 code-reviewer 看看...`        | 取决于 Claude 判断  | 快速委派   |
| @-mention | `@"code-reviewer (agent)" ...` | 保证执行一次         | 明确指定   |
| 整个会话      | `claude --agent code-reviewer` | 整个会话使用该 prompt | 专用工作模式 |

## Subagent 范围（Scope）优先级

| 位置 | 范围 | 优先级 | 创建方式 |
|---|---|---|---|
| Managed settings | 组织级 | 1（最高） | 管理员部署 |
| `--agents` CLI 参数 | 当前会话 | 2 | 启动时传入 JSON |
| `.claude/agents/` | 当前项目 | 3 | 文件创建，随 git 共享 |
| `~/.claude/agents/` | 所有项目 | 4 | 文件创建，个人通用 |
| 插件 `agents/` 目录 | 启用插件的项目 | 5（最低） | 插件安装 |

同名 subagent 时，优先级高的覆盖优先级低的。

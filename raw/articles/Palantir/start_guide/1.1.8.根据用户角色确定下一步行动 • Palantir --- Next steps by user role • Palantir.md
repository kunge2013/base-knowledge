## Data engineer 数据工程师

Palantir's data integration layer provides the foundation for all the other work that happens in the platform. By building and maintaining data pipelines, data engineers produce datasets that are high-quality, relevant, and frequently updated to serve the needs of the organization. A wide variety of tools are available to maintain the durability of data pipelines over time, including programmatic health checks and transparency into the underlying computation.  
Palantir 的数据集成层为平台上所有其他功能的运行提供了基础。通过构建和维护数据管道，数据工程师能够生成高质量、相关性强且更新频率高的数据集，以满足组织的需求。此外，还有多种工具可以帮助长期维护数据管道的稳定性，包括程序化的健康检查以及底层计算过程的透明化监控。

The primary tools used by data engineers include [**Pipeline Builder**](https://www.palantir.com/docs/foundry/pipeline-builder/overview/) and [**Code Repositories**](https://www.palantir.com/docs/foundry/code-repositories/overview/) for authoring data pipelines, and [**Data Lineage**](https://www.palantir.com/docs/foundry/data-lineage/overview/) for visualizing them end-to-end. Data engineers should also understand how to use [recommended health checks](https://www.palantir.com/docs/foundry/maintaining-pipelines/recommended-health-checks/), [monitoring views](https://www.palantir.com/docs/foundry/monitoring-views/overview/), and lineage to operate pipelines after they are deployed. Data engineers will need to be familiar with the concept of data pipelines and develop an understanding of what makes for a high-quality pipeline in the platform.  
数据工程师常用的主要工具包括：用于创建数据管道的 Pipeline Builder 和 Code Repositories，以及用于可视化数据流的 Data Lineage。数据工程师还应了解如何使用推荐的健康监测工具、监控界面以及数据流追溯功能，以便在管道部署后对其进行管理。此外，数据工程师需要熟悉数据管道的概念，并理解如何打造出高质量的数据管道。

[Learn more about data pipelines.  
了解更多关于数据管道的信息。](https://www.palantir.com/docs/foundry/data-integration/data-pipeline/)

## Application builder 应用程序构建工具

Palantir's Ontology and application building capabilities enable you to create tailored applications for end users. These end users are usually operators in an organization, making decisions that can be informed by data. Beyond just presenting data to users, you can use custom applications to capture information from users in the form of action types configured in the Ontology.  
Palantir 的本体技术和应用构建能力使你能够为终端用户创建定制化的应用程序。这些终端用户通常是组织中的决策者，他们的决策可以基于数据来进行支持。除了向用户展示数据之外，你还可以利用这些定制化的应用程序，根据用户在本体中定义的操作类型来收集信息。

Application builders will need to be familiar with the Palantir [**Ontology**](https://www.palantir.com/docs/foundry/ontology/overview/), which is usually the layer at which application builders collaborate with data engineers to establish a data foundation for workflow development. Builders can create and maintain their organization's Ontology in [**Ontology Manager**](https://www.palantir.com/docs/foundry/ontology-manager/overview/), then use [**Workflow Lineage**](https://www.palantir.com/docs/foundry/workflow-lineage/overview/) to understand how objects, actions, functions, large language models (LLMs), and applications fit together.  
应用程序构建者需要熟悉 Palantir 本体结构。通常，应用程序构建者与数据工程师会在这一层面合作，以建立适合工作流程开发的数据基础。构建者可以在 Ontology 管理工具中创建和维护其组织的本体结构，然后通过 Workflow Lineage 工具来理解各种对象、动作、功能、大型语言模型以及应用程序之间的相互关系。

To create and deliver applications, builders can use [**Workshop**](https://www.palantir.com/docs/foundry/workshop/overview/) for point-and-click application building on top of the Ontology, extend Workshop with [**custom widgets**](https://www.palantir.com/docs/foundry/custom-widgets/overview/), or use [**Pilot**](https://www.palantir.com/docs/foundry/pilot/overview/) to start from a natural language description. For code-first development, builders can use the [**OSDK**](https://www.palantir.com/docs/foundry/ontology-sdk/overview/) and [**OSDK React applications**](https://www.palantir.com/docs/foundry/ontology-sdk-react-applications/overview/), manage application configuration and SDK generation in [**Developer Console**](https://www.palantir.com/docs/foundry/developer-console/overview/), write [**Functions**](https://www.palantir.com/docs/foundry/functions/overview/) for shared business logic, or build applications in [**Slate**](https://www.palantir.com/docs/foundry/slate/overview/). Builders can also create LLM-backed workflows with [**AIP Logic**](https://www.palantir.com/docs/foundry/logic/overview/) and trigger ontology-driven work with [**Automate**](https://www.palantir.com/docs/foundry/automate/overview/).  
为了创建和交付应用程序，开发者可以使用 Workshop 工具来基于 Ontology 框架构建点击式应用程序。他们还可以使用自定义小部件来扩展 Workshop 的功能，或者借助 Pilot 工具从自然语言描述开始开发应用程序。对于以代码为主的发展方式，开发者可以使用 ODSDK 及 ODSDK React 应用程序，在 Developer Console 中管理应用程序配置和 SDK 生成，编写用于共享业务逻辑的函数，或者在 Slate 环境中构建应用程序。此外，开发者还可以使用 AIP Logic 创建基于 LLM 的工作流程，并通过 Automate 工具触发由 ontology 驱动的操作。

[Learn more about application building.  
了解更多关于应用程序构建的知识。](https://www.palantir.com/docs/foundry/app-building/overview/)

## Data scientist 数据科学家

The Palantir platform includes support for analyzing data using code and developing, evaluating, and deploying machine learning models. This functionality builds on top of the rigor of the data integration layer to provide lineage and reproducibility for models in the same way as datasets. The result is an environment where analytics and machine learning can build on high-quality data and shared modeling workflows.  
Palantir 平台支持使用代码来分析数据，以及开发、评估和实施机器学习模型。这一功能建立在数据集成层的严谨性之上，能够像处理数据集一样为模型提供可追踪性和可复现性。这样一来，分析技术和机器学习就能在高质量的数据和共享的建模工作流程上进行有效运作了。

In the Palantir platform, data scientists often use [**Code Workbook**](https://www.palantir.com/docs/foundry/code-workbook/overview/), an application designed to enable code-based analysis and the development of machine learning models. Code Workbook enables you to write code in Python, R, and SQL to access, normalize, and analyze high-quality datasets prepared by data engineers. The resulting analyses and models can then be connected to [model integration](https://www.palantir.com/docs/foundry/model-integration/overview/), shared through [**Model Catalog**](https://www.palantir.com/docs/foundry/model-catalog/overview/), evaluated with [**AIP Evals**](https://www.palantir.com/docs/foundry/aip-evals/overview/), and integrated into the Ontology for use in applications and workflows.  
在 Palantir 平台上，数据科学家经常使用 Code Workbook 这一工具。该工具旨在支持基于代码的分析和机器学习模型的开发。用户可以使用 Python、R 和 SQL 语言编写代码，以访问、整理和分析由数据工程师准备的高质量数据集。这些分析和模型随后可以连接到模型集成系统中，通过模型目录进行共享，并使用 AIP 评估工具进行评估，最终融入 Ontology 中，用于各种应用和工作流程中。

As an alternative, data scientists can work in their preferred third-party IDEs with [**Code Workspaces**](https://www.palantir.com/docs/foundry/code-workspaces/overview/). Code Workspaces containers are integrated with the rest of the Palantir ecosystem to combine JupyterLab® and RStudio® Workbench IDEs with the security, branching, and resource management benefits of the Palantir platform.  
作为一种替代方案，数据科学家可以在他们喜欢的第三方集成开发环境中进行工作。这些代码工作区与 Palantir 生态系统的其他组件紧密集成，能够将 JupyterLab®和 RStudio®工作区与 Palantir 平台的安全性、分支管理和资源管理功能相结合。

Learn more about [model integration](https://www.palantir.com/docs/foundry/model-integration/overview/) and [code-based analysis](https://www.palantir.com/docs/foundry/analytics/types-of-analysis/#code-based-analysis).  
了解更多关于模型集成和基于代码的分析技术的信息。

## Analyst 分析师

As Palantir can be used to build a secure and high-quality data foundation, analysts can find and explore data that is relevant to the questions they need to answer. A rich set of tools is available for analyzing data in a wide variety of formats—tabular, relational, temporal, geospatial, and more. Once your analysis yields insight, you can make it repeatable by creating [dashboards](https://www.palantir.com/docs/foundry/analytics/dashboards/) or present your findings using [reporting](https://www.palantir.com/docs/foundry/analytics/reporting/) tools.  
由于 Palantir 可以用于构建安全且高质量的数据基础，因此分析师能够找到并探索与他们需要解答的问题相关的数据。该工具套件提供了丰富的功能，可以分析各种格式的数据——包括表格数据、关系数据、时序数据、地理空间数据等。一旦分析得出有价值的见解，就可以通过创建仪表盘或使用报告工具来将分析结果呈现出来，从而让这些分析结果具有可重复性。

Analysts typically use [**Contour**](https://www.palantir.com/docs/foundry/contour/overview/) to explore datasets in the platform and conduct open-ended analysis at high-scale, and use [**Quiver**](https://www.palantir.com/docs/foundry/quiver/overview/) to analyze data in the Ontology, along with associated time series. Analysts can also use [**AIP Analyst**](https://www.palantir.com/docs/foundry/aip-analyst/overview/) to explore ontology-backed questions with natural language. These applications support moving from ad-hoc analysis into dashboards, reports, or [**Notepad**](https://www.palantir.com/docs/foundry/notepad/overview/) documents that share results with colleagues.  
分析师通常会使用 Contour 工具来探索平台中的数据集，并进行大规模的开放式分析。同时，他们还会使用 Quiver 工具来分析 ontology 中的数据以及相关的时间序列数据。此外，分析师还可以使用 AIP Analyst 工具，用自然语言来探索基于 ontology 的问题。这些工具支持从临时分析过渡到创建包含结果的仪表盘、报告或笔记文档，以便与同事共享分析结果。

[Learn more about analytics](https://www.palantir.com/docs/foundry/analytics/overview/).  
了解更多关于分析方面的知识。

## Platform administrator 平台管理员

Platform administrators can use Palantir's dedicated administrative tooling to configure the platform, manage and understand how it is being used, and ensure that the organization's data is being managed securely.  
平台管理员可以使用 Palantir 提供的专业管理工具来配置平台、管理和了解平台的使用情况，同时确保组织的数据得到安全管理。

Platform administrators typically set up [authentication](https://www.palantir.com/docs/foundry/authentication/overview/) to connect to an organization's identity provider, configure [application access](https://www.palantir.com/docs/foundry/administration/configure-application-access/), then set up [**Data Connection**](https://www.palantir.com/docs/foundry/data-connection/overview/) to enable data to flow into the platform. As use of the platform matures, administrators can use [**Resource Management**](https://www.palantir.com/docs/foundry/resource-management/overview/) to manage resource consumption, [**Developer Console**](https://www.palantir.com/docs/foundry/developer-console/overview/) to support custom application development, and [monitoring views](https://www.palantir.com/docs/foundry/monitoring-views/overview/) to help teams observe operational health. Administrators should also understand access considerations for [**Palantir MCP**](https://www.palantir.com/docs/foundry/palantir-mcp/security/) and [**Ontology MCP**](https://www.palantir.com/docs/foundry/ontology-mcp/overview/) when those capabilities are enabled.  
平台管理员通常会配置身份验证以连接企业的身份提供者，设置应用程序访问权限，然后建立数据连接，使数据能够流入平台。随着平台的不断成熟，管理员可以使用资源管理功能来管理资源消耗，通过开发者控制台来支持自定义应用程序的开发，同时利用监控界面来帮助团队了解系统的运行状况。此外，当 Palantir MCP 和 Ontology MCP 的功能被启用时，管理员还需要了解相关的访问规则。

[Learn more about platform administration.  
了解更多关于平台管理的相关信息。](https://www.palantir.com/docs/foundry/administration/overview/)

## Data governance 数据治理

Palantir provides tools for securing data and providing transparency to data governance leads. These tools provide guarantees about how data is protected as it is transformed in the Palantir platform and used for user-facing applications. They also preserve the ability for you to introspect and validate who has access to what information.  
Palantir 提供了一些工具，用于保护数据安全，并提升数据治理决策者的透明度。这些工具确保了数据在传输到 Palantir 平台以及被用于面向用户的应用程序时得到妥善保护。同时，这些工具还保留了用户审查并确认谁可以访问哪些信息的功能。

Users in data governance roles should learn about the broad set of data security workflows in the platform, ranging from [securing a data foundation](https://www.palantir.com/docs/foundry/security/securing-a-data-foundation/) to [protecting sensitive data](https://www.palantir.com/docs/foundry/security/protecting-sensitive-data/). These capabilities are built on Palantir's data security concepts, namely [**Projects**](https://www.palantir.com/docs/foundry/security/projects-and-roles/) and [**Markings**](https://www.palantir.com/docs/foundry/security/markings/). Governance leads should also understand [object permissioning](https://www.palantir.com/docs/foundry/object-permissioning/ontology-permissions/), [application restrictions](https://www.palantir.com/docs/foundry/developer-console/application-restrictions/), [OSDK permissions](https://www.palantir.com/docs/foundry/developer-console/permissions/), [Ontology MCP restrictions](https://www.palantir.com/docs/foundry/ontology-mcp/overview/), and [Workflow Lineage security visibility](https://www.palantir.com/docs/foundry/workflow-lineage/manage-security/) where those controls are part of their organization's workflows.  
处于数据治理职位的用户应了解平台上各种数据安全工作流程。这些工作流程涵盖了从保护数据基础到保护敏感数据等多个方面。这些功能基于 Palantir 的数据安全理念构建，具体包括项目管理和权限管理等方面。负责治理工作的人员还应了解对象权限管理、应用程序限制、OSDK 权限、Ontology MCP 限制以及工作流程溯源安全性等相关知识，因为这些控制措施都是其组织工作流程的一部分。

[Learn more about data protection and governance.  
了解更多关于数据保护和管理的知识。](https://www.palantir.com/docs/foundry/security/data-protection-and-governance/)

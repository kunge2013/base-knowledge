## Scenarios \[Beta\] 场景\[测试版\]

Beta

Ontology scenarios are in the [beta](https://www.palantir.com/docs/foundry/platform-overview/development-life-cycle/) phase of development and may not be available on your enrollment. Functionality may change during active development. Contact Palantir Support to request access to scenarios.  
Ontology 场景目前处于开发测试阶段，可能无法在您的订阅服务中使用。在开发过程中，其功能可能会发生变化。如果您希望使用这些场景，请联系 Palantir 的支持部门以获得访问权限。

With Ontology scenarios, you can create and compare "what-if" analyses using objects and the ontological concept of a model. A scenario is essentially a sandbox to apply edits on top of the data in your Ontology, generated by applying one or more actions.  
在 Ontology 场景中，你可以创建并比较“假设性”分析，这些分析利用了对象以及 Ontology 中的模型概念。实际上，一个场景就像一个沙箱，你可以在其中对 Ontology 中的数据进行编辑，而这些编辑可以通过执行一个或多个操作来实现。

## Common use cases 常见的使用场景

We recommend using Ontology scenarios for the following workflows:  
我们建议对于以下工作流程，使用 Ontology 场景：

- **What-if analysis:** Simulate changes to your data or system by creating an isolated fork of your Ontology, without affecting live data.  
	假设分析：通过创建 Ontology 的隔离版本来模拟对数据或系统的修改，而不会影响实际的数据。
- **Business logic simulation:** Apply actions and functions to simulate business processes or evaluate the impact of operational changes before committing them.  
	业务逻辑模拟：通过应用各种操作和函数来模拟商业流程，或在实施操作变更之前评估其影响。
- **Agent evaluation and forecasting:** Test agents against different input parameters to compare outcomes and refine predictions.  
	代理评估与预测：通过测试不同输入参数下的代理表现，来比较结果并优化预测模型。
- **Comparative analysis:** Create multiple scenarios side by side to identify the optimal decision or understand the trade-offs between different strategies.  
	比较分析：创建多个方案进行对比，以确定最佳决策方案，或了解不同策略之间的权衡关系。

Scenarios are not data versioning tools. They cannot provide a snapshot of your Ontology at a historical point in time and should not be used for that purpose.  
场景并不是数据版本控制工具。它们无法提供关于您 Ontology 在某一历史时刻的状态的快照，因此不应用于此目的。

## Time to live 是时候去死啦

To manage storage costs, a scenario has a default lifespan of 30 days. After 30 days, the scenario is automatically deleted along with all edits applied to that scenario and the backing persisted scenario object.  
为了管理存储成本，该场景的默认生命周期为 30 天。30 天后，该场景将被自动删除，同时所有对该场景所做的编辑操作以及相关的持久化场景对象也会一同消失。

## Auto-rebasing 自动重新定位

A scenario is auto-rebased every 10 minutes on top of their main or global branch. The rebase feature allows you to incorporate the latest changes from the base Ontology into your active scenario, keeping it in sync with the latest state of your data.  
该场景会每隔 10 分钟在主要或全局分支上进行自动合并。这种合并功能使得你可以将基础 Ontology 中的最新更改整合到当前场景中，从而确保你的场景始终与数据的最新状态保持同步。

## Global Branching vs. Ontology scenarios全球分支结构与本体论场景对比

[Global branching](https://www.palantir.com/docs/foundry/global-branching/overview/) is a tool used by builders to develop and test end-to-end workflows in the Palantir platform. These workflows would otherwise be too disruptive to run against a live production environment. An Ontology scenario provides a sandbox for users (humans and agents) of these workflows to apply edits to the Ontology without disrupting the main Ontology data. Users can create and compare multiple scenarios and merge edits to main Ontology data.  
全球分支功能是开发者用来开发和测试 Palantir 平台中端到端工作流程的工具。如果这些工作流程在实时生产环境中运行，将会对系统造成过大的干扰。通过 Ontology 场景，用户可以在一个隔离的环境中对 Ontology 数据进行修改，而不会影响到主 Ontology 数据。用户可以创建多个场景并进行比较，同时还可以将修改内容合并到主 Ontology 数据中。

## Functions on a scenario在场景中进行操作

All functions, except AIP Logic functions, can be run on a scenario as is. If the function reads from the Ontology, it will read the state of the Ontology on the scenario. If the function makes Ontology edits, it will make those edits on the scenario. Contact Palantir Support if you want to use AIP Logic on a scenario.  
除了 AIP 逻辑函数之外，所有函数都可以直接在场景中运行。如果某个函数从本体中读取数据，那么它会读取场景中本体的状态；如果该函数对本体进行编辑，那么它也会对场景中的本体进行编辑。如果您希望在场景中使用 AIP 逻辑，请联系 Palantir 支持部门。

## Limitations 局限性

Consider the following limitations when building out your workflow using scenarios:  
在通过场景来构建你的工作流程时，请考虑以下限制因素：

- Because merging a scenario uses an action, [apply action limits](https://www.palantir.com/docs/foundry/action-types/scale-property-limits/) apply to merging a scenario.  
	因为合并一个场景需要使用某个操作，所以对合并场景应用的操作限制也是适用的。
- Scenarios are auto-rebased every 10 minutes on top of their base.  
	这些场景会每隔 10 分钟自动更新一次，这已经是基于它们的基础时间了。
- Scenarios cannot be rebased at will or be configured with rebase intervals.  
	场景不能随意进行重定位，也不能配置重定位间隔。

## Use a Python function in Workshop在 Workshop 中使用一个 Python 函数

## Prerequisites 先决条件

This guide assumes you have already authored and published a Python function. Review the [getting started with Python functions](https://www.palantir.com/docs/foundry/functions/python-getting-started/) documentation for a tutorial. For examples of how to query the Ontology using the Python SDK, see the [Python Ontology SDK documentation](https://www.palantir.com/docs/foundry/ontology-sdk/python-osdk/).  
本指南假设您已经编写并发布了一个 Python 函数。有关入门教程，请参考《如何使用 Python 函数》文档。关于如何使用 Python SDK 查询 Ontology 的示例，请参阅 Python Ontology SDK 文档。

## Use the Python function in Workshop在研讨会中使用 Python 函数

In Workshop, search for the Python function from the **Variables** tab to the left side of the module. Both [serverless and deployed functions](https://www.palantir.com/docs/foundry/functions/functions-deployed/#choose-between-deployed-and-serverless-execution-modes) will appear here. Serverless functions can always be run at any version and do not need to be manually deployed. Deployed functions will show an icon with one of three states for both the function and the function version:  
在“工作区”中，从模块左侧的“变量”选项卡中搜索相应的 Python 函数。在这里会显示无服务器函数和已部署的函数。无服务器函数可以在任何版本上运行，无需手动部署。已部署的函数则会显示带有三种状态图标：代表函数本身、函数版本以及两者都有的状态。

- **Running:** This function and version can serve requests.  
	运行：这个函数及其版本可以处理各种请求。
- **Stopped:** This function and version are not available. In the function selector, hover over the information icon, select **Configure** and then **Create and start deployment** to make the function available.  
	已停止：该函数及其版本当前不可用。请在函数选择器中，将鼠标悬停在信息图标上，然后选择“配置”选项，接着点击“创建”以开始部署，从而使该函数可用。
- **Upgrading:** This function and version are not yet available.  
	升级：此功能和版本目前尚未提供。
![A Python function in Workshop](https://www.palantir.com/docs/resources/foundry/functions/python-functions-workshop-deployment-status.png?width=650px)

### Cut a new release发布新的版本吧。

Only one version of the function’s repository is hosted at a given time. To make changes to functions with limited downtime we recommend adding a new function (like `function_v1`) with the changes and tagging as described [here](https://www.palantir.com/docs/foundry/functions/python-getting-started/#commit-and-publish-a-function). From your published functions under tags and releases, select **Open in Ontology Manager**.  
在某一时刻，该函数的仓库只有一种版本可供使用。为了在最小化停机时间的情况下对函数进行修改，我们建议创建一个新的函数（例如 `function_v1` ），并应用所需的更改，同时按照此处描述的步骤进行标签标注。在已发布的函数中，通过标签和版本进行筛选，然后选择“在 Ontology Manager 中打开”。

In Ontology Manager, select the version of the function repository you want to use in applications, then select **Upgrade**.  
在 Ontology Manager 中，选择希望在应用中使用的函数仓库版本，然后点击“升级”按钮。

![Upgrade deployed function](https://www.palantir.com/docs/resources/foundry/functions/python-functions-upgrade-deployed-function.png?width=350px)

Update all downstream applications using functions from this repository to the new version you have deployed. Note that the previous deployment version will no longer be running so your applications will have a short downtime as you make this change. You will have `function_v0` and `function_v1` available at the same time so while you need to switch to the new deployment version, you do not have to change the function you are using. When `function_v0` is no longer used, you can delete the function.  
请使用此仓库中的函数更新所有下游应用程序，使其升级到新版本。请注意，旧的部署版本将不再运行，因此进行此更改时，应用程序的停机时间会很短。此时， `function_v0` 和 `function_v1` 都可以继续使用，因此当您需要切换到新版本时，无需更改所使用的函数。当 `function_v0` 不再被使用时，就可以删除该函数了。

### Debug errors 调试错误

If your function is not working as expected in Workshop, first check if the issue is related to the logic or the responsiveness of the function. If there is an issue with the logic, inspect the source code in the backing code repository. If there is an issue with the function being unresponsive or throwing an error, follow the steps below:  
如果您的函数在 Workshop 中的运行不符合预期，首先检查问题是由于逻辑方面的问题还是函数的响应速度问题。如果问题是逻辑上的，请查看后台代码仓库中的源代码。如果问题是函数无响应或抛出异常，请按照以下步骤进行处理：

1. Check if the version you selected is currently running in the function selector dropdown menu.  
	请检查您所选的版本是否正在函数选择器的下拉菜单中运行。
![Workshop function version selector.](https://www.palantir.com/docs/resources/foundry/functions/python-functions-workshop-function-selector-running.png?width=350px)
2. If the function is not deployed or `Upgrading`, hover over the function’s information icon and select **Configure**. This will take you to Ontology Manager where you can select **Start Deployment** to get your function running again.  
	如果该函数尚未部署，或者 `Upgrading` 处于未激活状态，请将鼠标悬停在函数的信息图标上，然后选择“配置”选项。这将带你进入 Ontology 管理器界面，在那里你可以选择“开始部署”，使该函数再次运行起来。
![Information about Python function version.](https://www.palantir.com/docs/resources/foundry/functions/python-functions-upgrading-function-info.png?width=750px)
3. If your function is `Running` or you need more information about the deployment’s behavior, select **Deployment** from the left panel in Ontology Manager to view detailed logs. SLS logs are also available if you select **View live**.
![View deployment logs in Ontology Manager.](https://www.palantir.com/docs/resources/foundry/functions/python-functions-deployed-function-logs.png?width=850px)

## Create a function-backed column

To create a function-backed column, you must publish a function that meets the following requirements:

- The function's input parameters must include an object set parameter (imported from `ontology_sdk.ontology.object_sets`) and can optionally include other input parameters. This object set parameter will enable the objects displayed in the table to be passed into the function to then generate the desired derived column. Note that a `list[ObjectType]` parameter will also work here, but this less performant option is not recommended.
- The function's return type must be `dict[ObjectType, ColumnType]`, where `ColumnType` is the desired [type](https://www.palantir.com/docs/foundry/functions/types-reference/#types-reference) for the column, or `dict[ObjectType, CustomType]` to return multiple columns from the function. Learn more about [custom types](https://www.palantir.com/docs/foundry/functions/types-reference/#structcustom-type).

Once a function that meets the above criteria is configured and published, you can configure a function-backed property column within the [Object Table](https://www.palantir.com/docs/foundry/workshop/widgets-object-table/#features-of-function-backed-properties) widget configuration.

An example of a function returning one column:

```python
Copied!from functions.api import Date, Integer, String, function
from ontology_sdk import FoundryClient
from ontology_sdk.ontology.object_sets import MyObjectTypeObjectSet
from ontology_sdk.ontology.objects import MyObjectType

@function
def function_backed_column_single_col(
    selected_objects: MyObjectTypeObjectSet
) -> dict[MyObjectType, Integer]:
    final_dict = {}

    for curr_obj in selected_objects:
        final_dict[curr_obj] = 10 # The value can be defined for any arbitrary logic

    return final_dict
```

An example of a function returning multiple columns:

```python
Copied!from dataclasses import dataclass

@dataclass
class CustomType:
    column_name_a: int
    column_name_b: int

@function
def function_backed_column_multiple_cols(
    selected_objects: MyObjectTypeObjectSet, some_other_parameter: String
) -> dict[MyObjectType, CustomType]:
    final_dict = {}

    for curr_obj in selected_objects:
        final_dict[curr_obj] = CustomType(column_name_a=10, column_name_b=20)

    return final_dict
```

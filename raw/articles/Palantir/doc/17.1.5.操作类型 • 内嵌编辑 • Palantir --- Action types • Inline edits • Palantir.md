## Inline edits 在线编辑

Action-backed inline edits are validated and submitted differently than standard [actions](https://www.palantir.com/docs/foundry/action-types/getting-started/). For standard actions, multiple parameters need to be set in order for the action to be valid. However, for action-backed inline edits, every parameter is optional and defaults to the existing value of the object, so a user can make individual changes to properties one at a time.  
基于操作的在线编辑在验证和提交方式上与标准操作有所不同。对于标准操作，需要设置多个参数才能使操作生效。而基于操作的在线编辑中，每个参数都是可选的，系统会默认使用对象原有的值，因此用户可以逐个修改对象的各个属性。

This documentation discusses how to avoid unexpected results when using inline edits. Inline edits are available in both Workshop and Object Explorer. The configuration of the inline edit action depends on where the action is used.  
这份文档介绍了如何在使用内嵌编辑功能时避免意外的结果。内嵌编辑功能既适用于工作区，也适用于对象浏览器。内嵌编辑功能的配置取决于其使用的场景。

## Object Explorer inline edits对象浏览器内编辑功能

Inline edits allow users to quickly edit values of an object in the [Object Explorer results view](https://www.palantir.com/docs/foundry/object-explorer/view-results/) or native Object View widgets, like the property or metric cards widget.  
在线编辑功能允许用户快速修改对象浏览器结果视图中的对象值，或者使用原生对象视图小工具来编辑数据，比如属性或度量卡小工具所显示的内容。

### Configuration 配置

![Inline edit action configuration](https://www.palantir.com/docs/resources/foundry/action-types/inline-action-configuration.png)

To set up an inline edit action, navigate to the **Properties** tab of your object type and then to the **Interaction** tab in Ontology Manager. Select a property and navigate to **Inline edit** in the sidebar. In the dropdown menu, select one of the available action types or create a new one. Creating a new one will trigger the action type creation workflow. Each property can have only one inline edit action type.  
要设置内嵌编辑操作，请先导航到目标对象的属性页面，然后进入 Ontology Manager 的“交互”选项卡。选择某个属性，在侧边栏中选择“内嵌编辑”选项。在下拉菜单中，可以选择已提供的操作类型之一，或者创建新的操作类型。创建新的操作类型会触发相应的创建流程。每个属性只能拥有一种内嵌编辑操作类型。

You can use the same action type as an inline edit for multiple properties, or you can have separate action types for different properties.  
你可以为多个属性使用相同的操作类型，或者为不同的属性设置不同的操作类型。

#### Action type requirements for inline edits内嵌编辑的操作类型要求

Not all action types can be used as inline edit action types. To be accepted, the action type must meet the following requirements:  
并非所有操作类型都可以用作内联编辑操作类型。要被接受，该操作类型必须满足以下要求：

- May only modify a single object of a single object type.  
	只能修改单个对象类型中的单个对象。
- Default values must be enabled.  
	必须启用默认值设置。
- Default values must come from the object reference parameter on which the inline action is defined. As a result, properties that are being changed in the action cannot be mapped to static values or special values like "Current User" or "Current Time".  
	默认值必须来自定义内联动作的对象引用参数。因此，在动作中修改的属性无法映射到静态值或特殊值，比如“当前用户”或“当前时间”。
- Visibility status and overrides can be set; however, they will be ignored if the inline edit is used in Object Explorer and Object Views.  
	可以设置可见性状态和覆盖选项；不过，如果在使用对象浏览器和对象视图进行内联编辑时，这些设置将被忽略。
- [Side effect webhooks](https://www.palantir.com/docs/foundry/action-types/webhooks/#webhooks-writeback-vs-side-effect) or [side effect notifications](https://www.palantir.com/docs/foundry/action-types/notifications/) cannot be enabled.  
	无法启用副作用 Web 钩子或副作用通知功能。

## Workshop inline edits 研讨会内编辑功能

No additional configuration is required to use an action type as an inline edit in Workshop, but not all actions are suitable for cell-level editing. For information on how to configure inline edits, see the [Workshop documentation](https://www.palantir.com/docs/foundry/workshop/widgets-object-table/#inline-edits-cell-level-writeback).  
在 Workshop 中，使用动作类型作为内嵌编辑功能并不需要额外的配置。不过，并非所有动作都适用于单元格级别的编辑。有关如何配置内嵌编辑功能的详细信息，请参考 Workshop 的文档。

### Background 背景信息

When running a single action, edits are validated and submitted one at a time (sequentially). Inline edits differ in that they are validated and submitted in bulk. Because of this, not all actions are suitable for inline edits. Actions that may fail or have unexpected results due to inline edits include:  
在执行单个操作时，编辑内容会逐一进行验证和提交。而在线编辑则不同，它的是批量进行验证和提交。因此，并非所有操作都适合在线编辑。那些由于在线编辑而可能导致失败或产生意外结果的操作包括：

- Any action that attempts to read data to which another action could have written, or  
	任何试图读取可以被其他操作写入数据的操作，或者…
- Two actions that try to write to the same object.  
	有两个操作试图对同一个对象进行写入操作。

When inline edits are applied to a [Scenario](https://www.palantir.com/docs/foundry/workshop/scenarios-overview/), the submitted actions are applied sequentially (in a non-deterministic order) rather than simultaneously (as is normally the case with inline edits). As a result, inline edit actions that ordinarily fail due to multiple actions trying to write to the same object may succeed when applied to a scenario, though we do not recommend building applications that depend upon this difference in behavior.  
当对场景进行内嵌式编辑时，所提交的操作会按非确定性顺序依次执行，而不是像常规内嵌式编辑那样同时执行。因此，那些由于多个操作试图同时修改同一个对象而通常会导致失败的内嵌式编辑操作，在应用于场景时可能会成功执行。不过，我们并不建议构建依赖于这种行为差异的应用程序。

### Valid inline Actions 有效的内联操作

Actions must submit non-conflicting edits to be effective as Action-backed inline edits. In practice, this means multiple Actions configured in the same table edit widget must not:  
这些操作必须提交不冲突的编辑内容，才能作为受动作支持的嵌入编辑而生效。实际上，这意味着在同一表格编辑工具中配置的多个动作不得相互冲突。

- Write to the same object,  
	同时写入同一个对象。
- Create the same link, or  
	创建相同的链接即可。
- Attempt to keep aggregate values consistent.  
	尽量保持各数值的一致性。

### Invalid inline Actions 无效的内联操作

**Actions will return an error if an inline edit attempts to edit the same object twice.** Also, adding or deleting join table links is not supported by inline edits and will result in a user-facing error message.  
如果内嵌编辑尝试两次编辑同一个对象，将会出现错误。此外，内嵌编辑不支持添加或删除关联表的链接操作，这样做会导致用户看到相应的错误信息。

As users apply inline edits, [submission criteria](https://www.palantir.com/docs/foundry/action-types/submission-criteria/) will be applied to each edit, but the edits will be submitted in bulk. Both parameter and global submission criteria will be evaluated for each edited object, but submission criteria that reference shared or linked objects are not compatible with inline edits. This is because when applying inline edits, cumulative submission criteria compare the edited value to the unedited values for the column. At final submission, the edits will be submitted all at once and will succeed if they all pass parameter and global submission criteria for the corresponding object.

Submission criteria on objects shared between multiple Action types or linked objects are therefore evaluated once per edit, before any edits are made.  
因此，对于由多个操作类型或关联对象共同使用的对象，提交标准会在每次编辑之前进行一次性评估。在做出任何修改之前，都会先对这部分内容进行审核。

Submission criteria that reference shared Action types or linked objects are not compatible with inline edits, and bulk updating objects could violate submission criteria rules that work as expected when applied sequentially (one at a time).  
那些引用共享动作类型或链接对象的提交标准，与内联编辑方式不兼容。同时，批量更新对象的行为可能会违反提交标准规则，而如果这些规则按预期顺序执行（一次只处理一个对象），那么这些规则仍然可以正常发挥作用。

#### Example: Invalid inline Actions示例：无效的内联操作

Imagine a `Delay Flight` Action that can delay a single flight by a maximum of 20 minutes at an airport that can delay all flights by a maximum of 50 minutes.  
想象一种 `Delay Flight` 操作，它能够将某个航班的起飞时间最多延迟 20 分钟，而该机场所有航班的延迟时间最多为 50 分钟。

- Both submission criteria – the 20 minute requirement and the 50 minute total – will be evaluated each time a cell is updated.  
	在每次更新单元格信息时，都会对这两个标准进行评估：20 分钟的提交时间限制，以及总共 50 分钟的时间限制。
	- Because no edits are yet submitted, the 50 minute total will compare the new delays to the sum of unedited delays in the column (the delays from before inline editing began).  
		由于目前还没有任何编辑内容被提交，因此 50 分钟的总时长将用来比较新的延迟情况与未编辑时的延迟总和。未编辑时的延迟数据指的是在在线编辑开始之前所记录的延迟情况。
- The second submission criteria (that all the delays at the airport sum to less than 50 minutes) relies on an aggregated value and is shared by all the objects in the column.  
	第二个评判标准（即机场内所有延误时间总和不超过 50 分钟）是基于一个汇总值，该值被该列中的所有对象共同共享。
	- Since inline edits are submitted in bulk, this second submission criteria will not be effective in limiting the total duration of flight delays at a given airport; the resulting edits could sum to greater than the 50 allowed by the second submission criteria.  
		由于内嵌编辑的内容是批量提交的，因此第二个提交标准在限制特定机场的航班延误总时长方面将不起作用；这样一来，提交的内容总和可能会超过第二个标准所允许的 50 个限制。
- This Action would not be suitable for table editing as it would cause inconsistent results compared to running the Action individually for each cell.  
	此操作不适合用于表格编辑，因为与单独对每个单元格执行该操作相比，结果可能会不一致。

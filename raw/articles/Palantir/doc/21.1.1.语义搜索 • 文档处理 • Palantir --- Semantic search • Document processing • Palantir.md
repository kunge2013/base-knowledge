## Document processing 文档处理

This page will discuss a few useful considerations for extracting data from a PDF document or image.  
这一页将讨论一些从 PDF 文档或图像中提取数据时的实用技巧。

## Data extraction 数据提取

This page offers a basic guide for using [Pipeline Builder](https://www.palantir.com/docs/foundry/pipeline-builder/overview/) to parse PDFs for semantic search and includes a recommendation for presenting the information in a [Workshop](https://www.palantir.com/docs/foundry/workshop/overview/) application when you just have text content.  
此页面提供了使用 Pipeline Builder 解析 PDF 文件以进行语义搜索的基本指南。同时，建议在仅包含文本内容时，将信息以研讨会应用程序的形式呈现。

Semantic search is a powerful tool to use with PDFs, particularly if the content is broken down into smaller "chunks" that are embedded separately, helping users and workflows find important information that might otherwise be hard to access. This is especially useful considering the vast amount of unstructured knowledge in PDFs that often goes unnoticed.  
语义搜索是一种非常有用的工具，适用于处理 PDF 文件。特别是当内容被分解成多个较小的“块”并分别嵌入时，它能帮助用户和工作流程更快地找到那些难以被发现的关键信息。考虑到 PDF 文件中往往存在大量未被注意到的非结构化知识，这种搜索方式显得尤为重要。

To use, simply upload your PDFs to Foundry, extract the text, chunk the same text, search for those chunks, and surface the results of that search with the corresponding PDF rendered on the side for source-of-truth cross-validation for the users.  
使用方式非常简单：只需将您的 PDF 文件上传到 Foundry 平台，提取其中的文本，将相同的文本分组，然后搜索这些分组内容。搜索结果会显示在页面上，同时还会附带对应的 PDF 文件，以便用户进行验证和交叉验证。

Follow the steps outlined below to import PDFs and extract text from PDFs:  
按照以下步骤来导入 PDF 文件并提取其中的文本：

1. [Import the PDFs as a media set](https://www.palantir.com/docs/foundry/data-integration/media-sets/).  
	将 PDF 文件作为媒体集进行导入。
2. [Add the media set to Pipeline Builder](https://www.palantir.com/docs/foundry/pipeline-builder/datasets-add/#add-data-from-foundry-to-pipeline-builder).  
	将媒体文件添加到 Pipeline Builder 中。
3. Use the **Get Media References** board.  
	使用“获取媒体引用”板。

![Get Media References board](https://www.palantir.com/docs/resources/foundry/ontology/get-media-references.png)

4. Use the **Text Extraction** board.  
	使用文本提取板。

![Text Extraction board](https://www.palantir.com/docs/resources/foundry/ontology/text-extraction.png)

## Chunking 分块处理

This page outlines how to incorporate a basic chunking strategy into your [semantic search](https://www.palantir.com/docs/foundry/ontology/overview-semantic-search/) workflows. Chunking, in this context, means breaking up larger pieces of text into smaller pieces of text. This is advantageous because embedding models possess a maximum input length for text, and crucially, smaller pieces of text will be more semantically distinct during searches. Chunking is often used when parsing large documents like [PDFs](#data-extraction).  
本页面介绍了如何将基本的分块策略融入您的语义搜索工作流程中。在这里，分块指的是将较长的文本分割成较短的段落。这样做的好处是，由于模型的最大输入文本长度有限，而较小的文本片段在搜索时更具语义独立性。在解析像 PDF 这样的大型文档时，通常会使用分块技术。

Primarily, the objective is to split long text into smaller "chunks", each with an associated Ontology object [linked](https://www.palantir.com/docs/foundry/object-link-types/create-link-type/) back to the original object.  
主要目的是将较长的文本分割成较小的“段落”，每个段落都包含一个与之相关的本体对象，该对象可以链接到原始对象上。

Where does chunking happen?  
分组现象发生在何处呢？

Chunking is performed by the **Chunk string** board in [Pipeline Builder](https://www.palantir.com/docs/foundry/pipeline-builder/overview/). Add the board from the transform menu, then configure the following arguments:  
在 Pipeline Builder 中，分块操作是由 Chunk 字符串板来执行的。从转换菜单中添加该板，然后配置以下参数：

- **Expression:** The text column you want to split into chunks.  
	表达式：你需要将其拆分成多个部分的文本列。
- **Chunk size:** The approximate number of characters in each chunk.  
	块大小：每个块中大约包含的字符数。
- **Chunk overlap:** The number of characters each chunk shares with the previous chunk, which helps preserve context across chunk boundaries.  
	块重叠：每个块与前一个块共享的字符数量，这有助于在各个块之间保持上下文的连贯性。
- **Separators:** An ordered, prioritized list of separators the board uses to split the text. The board splits on the highest priority separator first and only moves to the next separator when a chunk is still larger than the chunk size.  
	分隔符：一个有序的、带有优先级的列表，表示板块用来分割文本的分隔符。板块会按照优先级最高的分隔符进行分割，只有当待分割的文本块仍然大于指定的大小时，才会继续处理下一个分隔符。

For the full argument reference, see the [Chunk string](https://www.palantir.com/docs/foundry/pb-functions-expression/chunkStringV1/) function documentation.  
关于完整的参数说明，请参考 Chunk 字符串函数的文档。

## Chunking example 分块示例

As a starting point, we will show how a basic chunking strategy can be accomplished without using code in [Pipeline Builder](https://www.palantir.com/docs/foundry/pipeline-builder/overview/). For more advanced strategies, we recommend using a [code repository](https://www.palantir.com/docs/foundry/code-repositories/overview/) as part of your pipeline.  
作为起点，我们将展示如何在不使用 Pipeline Builder 中的代码的情况下实现基本的分块策略。对于更高级的策略，我们建议将代码存储在一个代码仓库中，作为流程的一部分。

For illustrative purposes, we will use a simple two row dataset with two columns, `object_id` and `object_text`. For ease of understanding, the `object_text` examples below are purposefully short.  
为了便于说明，我们将使用一个简单的两行数据集，包含两列： `object_id` 和 `object_text` 。为了便于理解，下面的 `object_text` 示例故意设计得比较简短。

| object\_id 对象 ID | object\_text 对象文本 |
| --- | --- |
| abc | gold ring lost 丢失了金戒指 |
| xyz | fast cars zoom 快速行驶的汽车 |

We initiate the process by employing the **Chunk String** board, which introduces an extra column containing an array of `object_text` segmented into smaller pieces. The board accommodates various chunking approaches, such as overlap and separators, to ensure that each semantic concept remains coherent and unique.  
我们采用“块字符串”结构来启动这一过程。该结构引入了一列额外的元素，这些元素被分割成更小的片段。这种结构支持多种分段方式，比如重叠和分隔符的使用，从而确保每个语义概念都保持连贯且独特的特点。

The below screenshot of a **Chunk String** board shows a simple strategy which you may alter for use toward your own use case. The below configuration would attempt to return chunks that are roughly 256 characters in size. Effectively, the board splits text on the highest priority separator until each chunk is equal to or smaller than the chunk size. If there are no more highest priority separators to split on and some chunks are still too large, it moves to the next separator until either all the chunks are equal or smaller than the chunk size or there are no more separators to use. Finally, the board will ensure that for each chunk identified, the chunk following has an overlap that covers the last 20 characters of the previous chunk.  
下面这张 Chunk String 板的截图展示了一种简单的策略，你可以根据自己的情况对其进行调整。该配置试图返回大小约为 256 个字符的块。实际上，该板会在最优先的分隔符处将文本分割，直到每个块的大小等于或小于指定的块大小。如果已经没有可用的分隔符来分割文本，而某些块仍然太大，那么系统会继续使用下一个分隔符，直到所有块的大小都符合要求，或者没有更多的分隔符可用为止。最后，该板会确保每个被识别出的块后面都有一个重叠区域，这个重叠区域能够覆盖前一个块的最后 20 个字符。

![Chunk string board](https://www.palantir.com/docs/resources/foundry/ontology/chunk-string-board.png)

| object\_id 对象 ID | object\_text 对象文本 | chunks 块状物 |
| --- | --- | --- |
| abc | gold ring lost 丢失了金戒指 | \[gold,ring,lost\] \[金子、戒指、丢失\] |
| xyz | fast cars zoom 快速行驶的汽车 | \[fast,cars,zoom\] \[快速、汽车、变焦\] |

Next we want each element in the array to have its own row. We will use the **Explode Array with Position** board to transform our dataset to one with six rows. The new column in each of the rows (as seen below) is a struct (map) with two key-value pairs, the position in the array and the element in the array.  
接下来，我们希望数组中的每个元素都能拥有属于自己的行。我们将使用“Explode Array”功能结合“Position Board”工具，将数据集转换为六行结构。在每一行中，新增加的列是一个结构体，包含两个键值对：一个表示在数组中的位置，另一个表示数组中的具体元素。

![Explode chunks.](https://www.palantir.com/docs/resources/foundry/ontology/explode-chunks.png)

| --- | --- | --- | --- |
| abc | gold ring lost 丢失了金戒指 | \[gold,ring,lost\] \[金子、戒指、丢失\] | {position:0, element} |

| abc | gold ring lost 丢失了金戒指 | \[gold,ring,lost\] \[金子、戒指、丢失\] | {position:2, element} |
| xyz | fast cars zoom 快速行驶的汽车 | \[fast,cars,zoom\] | {position:0, element} |
| xyz | fast cars zoom 快速行驶的汽车 | \[fast,cars,zoom\] | {position:1, element} |
| xyz | fast cars zoom 快速行驶的汽车 | \[fast,cars,zoom\] | {position:2, element} |

To create a unique identifier for each chunk, we will convert the chunk position in its array to a string and then concatenate it to the original object ID. We will also drop the unnecessary columns.  
为了为每个数据块创建一个唯一的标识符，我们将把数据块在数组中的位置转换为字符串，然后将其与原始对象 ID 连接在一起。同时，我们也会删除那些不需要的列。

![Drop unnecessary object_text, chunks, position, and chunks_with_position columns.](https://www.palantir.com/docs/resources/foundry/ontology/drop-unnecessary-columns.png)

| object\_id 对象 ID | chunk | chunk\_id |
| --- | --- | --- |
| abc | gold | abc\_0 |
| abc | ring | abc\_1 |
| abc | lost | abc\_2 |
| xyz | fast | xyz\_0 |
| xyz | cars | xyz\_1 |
| xyz | zoom | xyz\_2 |

Now, we have six rows representing six different chunks, each with the `object_id` (for linking), the new `chunk_id` to be a new primary key, and the `chunk` to be embedded as described in [semantic search workflow](https://www.palantir.com/docs/foundry/ontology/using-palantir-provided-models-to-create-a-semantic-search-workflow/#generate-embeddings-and-create-object-type). | xyz | fast | xyz\_0 | \[0.3,...,-0.5\] |

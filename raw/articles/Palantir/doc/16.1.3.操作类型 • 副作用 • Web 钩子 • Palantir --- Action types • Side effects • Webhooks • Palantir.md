## Webhooks

A [webhook](https://www.palantir.com/docs/foundry/data-connection/webhooks-overview/) is a concept in Data Connection that enables sending a request to an external system, such as Salesforce, SAP, or any configured HTTP server, typically to modify data in that external system.  
Webhook 是数据连接中的一个概念，它允许向外部系统发送请求，例如 Salesforce、SAP 或任何已配置的 HTTP 服务器，通常用于修改该外部系统中的数据。

By setting up a webhook and then configuring it for use in an action, you can send data to an external system when end users apply an action in Foundry. This enables workflows in Foundry to connect directly with source systems and write back data and decisions into those systems.  
通过设置 Web 钩子并对其进行配置，可以在最终用户在 Foundry 中触发某个动作时，将数据发送到外部系统。这样，Foundry 中的工作流程就能直接连接到源系统，并将数据和决策写回这些系统中。

This section details the various options available for configuring webhooks in an action. For a step-by-step tutorial, see the documentation on [how to add a webhook in an action](https://www.palantir.com/docs/foundry/action-types/set-up-webhook/).  
本节详细介绍了在动作中配置 Web 钩子功能的各种选项。如需了解详细的步骤说明，请参阅关于如何在动作中添加 Web 钩子的文档。

## Webhooks: Writeback vs. side effectWebhooks：写入与产生副作用的区别

There are two ways that webhooks can be configured for use in an action: as a **writeback** or as a **side effect**.  
在配置 Web 钩子以用于某个动作时，有两种方式可以使用：一种是作为写入操作的一部分，另一种则是作为副作用来使用。

![Add webhook](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-add-webhook.png?width=400)

For convenience, below is a table comparing the behavior of writeback and side effect webhooks.  
为了便于理解，下面提供了一个表格，对比了写回操作和副作用钩子的行为。

| Type 类型 | When applied 当应用时 | Failure shown to end user?   对最终用户来说，这似乎是一种失败吧？ | Timing 时机把握 |
| --- | --- | --- | --- |
| **Writeback 回写** | Before object changes 在对象发生变化之前 | Yes 是的 | Before user sees success or failure   在用户看到成功或失败的结果之前 |
| **Side effect 副作用** | After object changes 在对象发生更改之后 | No 没有 | May be after user sees success message   可能在用户看到成功消息之后发生 |

The following sections describe writeback webhooks and side effect webhooks in more detail.  
以下部分将详细阐述回写 Web 钩子和副作用 Web 钩子。

### Writeback webhooks 写入事件 Web 钩子

When configured as a **writeback**, the webhook will be executed *before* any other rules are evaluated; if the webhook execution fails, no other changes will be made. If you want to ensure that changes are not made in Foundry before the external system, you should set up your webhook as a writeback.  
当配置为回写模式时，webhook 会在其他任何规则被评估之前被执行；如果 webhook 执行失败，那么就不会进行任何其他更改了。如果您希望确保在外部系统做出更改之前，Foundry 不会进行任何操作，那么应该将 webhook 设置为回写模式。

This behavior enables some degree of transactionality between Foundry and the external system. Using a writeback webhook guarantees that if the request to the external system fails, no changes will be applied to the Foundry Ontology. However, it is still possible that the external request may succeed but Ontology changes could fail.  
这种行为使得 Foundry 与外部系统之间能够实现一定程度的事务处理。通过使用写回 Web 钩子机制，可以确保在向外部系统发起请求失败时，不会对 Foundry 的 Ontology 产生任何更改。不过，仍然有可能外部请求能够成功执行，但 Ontology 的更改却未能生效。

Because the action stops being applied when a writeback webhook fails, you can only configure a single webhook as a writeback. If this webhook fails when the action is applied, an error will be shown to the end user describing the failure.  
因为当写回钩子操作失败时，该操作将不再生效。因此，你只能配置一个写回钩子。如果在这个钩子操作执行过程中发生失败，将会向最终用户显示一个描述失败原因的错误信息。

When a webhook is configured as a writeback, its output parameters can be used in subsequent rules. See the [output parameters](#output-parameters) section below for more details.  
当 Web 钩子被配置为“写回”模式时，其输出参数可以在后续的规则中使用。更多详细信息请参见下面的输出参数部分。

### Side effect webhooks 副作用 Web 钩子

When configured as a **side effect**, a webhook will be executed *after* other rules are evaluated. This means that modifications to Foundry objects will occur before side effects are applied. You can configure multiple side effect webhooks in a single action, and they will be executed in no particular order. In an action with side effect webhooks, the end user will see a success message after Foundry objects are modified; executing the side effects may happen after the success message is shown.  
当配置为副作用时，webhook 会在其他规则评估完成后执行。这意味着对 Foundry 对象的修改会在副作用生效之前就发生。你可以在一个操作中配置多个副作用 webhook，并且它们的执行顺序是不固定的。在包含副作用 webhook 的操作中，当用户看到 Foundry 对象的修改结果后，会收到一个成功消息；而副作用的执行可能会在该消息显示之后才发生。

If you need to call a webhook multiple times from a single action, this can be achieved with a side effect webhook by providing a list of payloads as an input. This will trigger the webhook as many times as there are payloads in the list provided and will be processed in no guaranteed order. An example of this can be found below in the [input parameters](#input-parameters) section.  
如果您需要在一个操作中多次调用 web 钩子函数，可以通过提供一个包含多个负载的列表作为输入参数来实现这一点。这样，web 钩子函数就会根据列表中负载的数量进行触发，而且这些触发顺序是不确定的。下面在输入参数部分有一个具体的例子。

You should use side effect webhooks when you want to send best-effort notifications or write back to multiple external systems.  
当你想要发送优先级的通知或向多个外部系统写入数据时，应该使用副作用 Web 钩子。

## Input parameters 输入参数

In order to configure a Webhook in an Action, you must populate all of its required input parameters. General reference material about Webhook input parameters is available in the [Data Connection documentation](https://www.palantir.com/docs/foundry/data-connection/webhooks-reference/#input-parameters).  
为了配置动作中的 Web 钩子功能，必须填写所有必要的输入参数。关于 Web 钩子输入参数的相关参考信息，可以在数据连接文档中找到。

There are two ways to configure Webhook input parameters: by mapping to Action parameters, or by using a Function.  
配置 Webhook 输入参数有两种方式：一种是将其映射到动作参数中，另一种则是使用函数来进行处理。

When mapping to **Action parameters**, each required Webhook input must be set to either an Action parameter of the same type, a static value, or a property of an object parameter.  
在映射到 Action 参数时，每个必需的 Webhook 输入必须设置为同一类型的 Action 参数、静态值，或者对象参数的属性。

![Input parameters](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-input-parameters.png?width=400)

When using a [Function](https://www.palantir.com/docs/foundry/functions/overview/), you must select a Function that returns a custom type that includes all of the required Webhook input parameters and strongly matches the Webhook type, otherwise you will receive an `OntologyMetadata:ActionWebhookInputsDoNotHaveExpectedType` error. Using a Function to populate Webhook input parameters can be useful when you want to use logic to populate inputs, especially if this logic is based on Ontology objects. For example, you can retrieve linked objects and pull property values from those objects to prepopulate Webhook inputs.  
在使用函数时，必须选择能够返回自定义类型函数的函数，该函数应包含所有必需的 Webhook 输入参数，并且与 Webhook 类型高度匹配。否则，将会出现 `OntologyMetadata:ActionWebhookInputsDoNotHaveExpectedType` 错误。当需要使用逻辑来填充输入参数时，可以使用函数来实现这一功能，尤其是当这种逻辑基于 Ontology 对象时。例如，可以检索关联的对象，并从这些对象中提取属性值，以预先填充 Webhook 输入参数。

As an example, suppose you have a Webhook which takes three input parameters with IDs `name`, `industry`, and `country`:  
例如，假设你有一个 Web 钩子函数，该函数需要接收三个输入参数，它们的 ID 分别为 `name` 、 `industry` 和 `country` 。

![Input parameters example](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-input-parameters-example.png?width=400)

You can write a Function that returns a custom interface of the same structure:  
你可以编写一个函数，该函数返回具有相同结构的自定义接口：

```typescript
Copied!export interface MyWebhookInput {
    name: string;
    industry: string;
    country: string;
}
```

Then, you can select this Function when configuring Webhook inputs in an Action, mapping Action parameters to the parameters required by the Function:  
因此，在配置动作的 Webhook 输入时，你可以选择这个函数。将动作参数与该函数所需的参数进行关联即可。

![Mapping Action parameters to the parameters required by a Function](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-input-parameters-define-using-action.png?width=400)

Below is a full code example of a Function that loads data from an Ontology object and uses it to populate Webhook inputs.  
以下是演示如何从 Ontology 对象加载数据并将其用于填充 Webhook 输入的完整代码示例。

```typescript
Copied!import { Function, UserFacingError } from "@foundry/functions-api";
import { Company } from "@foundry/ontology-api";

export interface MyWebhookInput {
    name: string;
    industry: string;
    country: string;
}

export class MyWebhookFunctions {
    @Function()
    public returnWebhookInput(company: Company): MyWebhookInput {
        if (!company.name || !company.industry || !company.country) {
            throw new UserFacingError("Some required fields are not set.");
        }
        return {
            name: company.name,
            industry: company.industry,
            country: company.country,
        }
    }
}
```

A side effect Webhook may be called multiple times by returning a list of payloads from a Function. Below is an example Function which takes two companies as inputs, and returns a list containing two payloads matching the input parameters expected by a Webhook. If this Function is used from Actions to return the inputs for a side effect Webhook, it will result in two separate Webhook executions.  
Webhook 的一个副作用是，它可能会通过从函数中获取一系列负载来多次调用该函数。下面是一个示例函数，该函数接受两家公司作为输入，并返回一个包含两个负载的列表，这两个负载符合 Webhook 所期望的输入参数。如果此函数通过 Actions 被调用，以触发副作用 Webhook 的调用，那么就会触发两次独立的 Webhook 调用。

```typescript
Copied!import { Function } from "@foundry/functions-api";
import { Company } from "@foundry/ontology-api";

export interface MyWebhookInput {
    arg1: string;
    arg2: string;
}

export class MyFunctions {
    @Function()
    public createWebhookRequest(company1: Company, company2: Company): MyWebhookInput[] {
        return [
        {
           arg1: company1.someProperty,
           arg2: company1.someOtherProperty,
        },
        {
           arg1: company2.someProperty,
           arg2: company2.someOtherProperty,
        }
        ];
    }
}
```

## Output parameters 输出参数

When a Webhook is configured as a [writeback Webhook](#writeback-webhooks), you can use its output parameters in subsequent rules. This is useful when the external system returns data that you want to immediately write into a Foundry object or use in a subsequent [notification](https://www.palantir.com/docs/foundry/action-types/notifications/) or [side effect Webhook](#side-effect-webhooks).  
当将 Web 钩子配置为回写型 Web 钩子时，你可以在其输出参数中嵌入数据，这些数据可以用于后续的规则中。当外部系统返回的数据需要立即写入某个 Foundry 对象，或者用于后续的通知或附加 Web 钩子操作时，这一点非常有用。

General reference material about Webhook output parameters is available in the [Data Connection documentation](https://www.palantir.com/docs/foundry/data-connection/webhooks-reference/#output-parameters).  
关于 Webhook 输出参数的通用参考信息可以在数据连接文档中找到。

To use an output parameter in a subsequent logic rule, select **Writeback response** when populating the value for a logic rule, then select the specific output you wish to use:  
如果在后续的逻辑规则中需要使用输出参数，那么在为逻辑规则填充值时，请选择“Writeback response”；然后选择你想要使用的具体输出内容。

![Using an output parameters in a Logic Rule](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-output-parameters-in-logic-rule.png?width=400)

## OAuth 2.0 authenticationOAuth 2.0 认证机制

When a webhook is configured on a REST API source that uses an [outbound application](https://www.palantir.com/docs/foundry/administration/configure-outbound-applications/) for authentication, Foundry manages the OAuth 2.0 authorization flow on behalf of the user. Developers do not need to handle token acquisition or refresh. Foundry passes the correct access token with every webhook call.  
当某个 REST API 源配置了 Web 钩子功能，并且该 API 使用外部应用程序进行身份验证时，Foundry 会代表用户管理 OAuth 2.0 授权流程。开发者无需处理令牌的获取或刷新相关操作。每次调用 Web 钩子时，Foundry 都会传递正确的访问令牌。

For a full overview of OAuth 2.0 outbound application support across Foundry workflows, see the [OAuth 2.0 outbound applications](https://www.palantir.com/docs/foundry/administration/configure-outbound-applications/) documentation.  
关于 OAuth 2.0 在 Foundry 工作流程中对外应用程序支持的详细信息，请参阅 OAuth 2.0 对外应用程序文档。

## Rules 规则

**Rules** define the logic of the action type that transform the parameters into Ontology edits or other effects. There are two main types of rules: ones that edit the Ontology, and ones that trigger another effect in Foundry.  
规则定义了该行为类型的逻辑，它们将参数转化为本体编辑或其他效果。规则主要有两种类型：一种是对本体进行编辑的规则，另一种则是触发在 Foundry 中产生的其他效果的规则。

## Ontology rules 本体规则

An Ontology rule changes specific elements of the Ontology. They can create, modify, or delete objects and links of existing types. To create or delete one-to-many or one-to-one links, object rules need to be used and the foreign key property on the object needs to be modified.  
ontology 规则可以修改 ontology 中的特定元素。它们可以创建、修改或删除现有类型的对象和链接。若要创建或删除一对多或一对一的链接，就需要使用对象规则，并且需要修改对象上的外键属性。

1. **Create object:** Can be used to create an object of a predefined type. The primary key of the object type is a required property which has to be filled. Additional properties can be added optionally.  
	创建对象：可以用来创建预定义类型的对象。该对象类型的主键是一个必填属性，必须予以填充。也可以选择性地添加其他属性。
2. **Modify object(s):** Can be used to modify an existing object whose primary key is derived from object reference parameters. This cannot reference an object created as a part of the current action.  
	修改对象：可以用于修改那些主键来自对象引用参数的现有对象。不过，无法引用在当前操作过程中创建出来的对象。
3. **Create or modify object(s):** Can be used to modify an existing object based on an object reference parameter. If an object is not selected, a new object will be created with either an automatically generated unique ID, or with a user submitted primary key.  
	创建或修改对象：可以根据对象引用参数来修改现有的对象。如果对象未被选中，则会创建一个新对象，新对象的唯一 ID 可以由系统自动生成，或者由用户提供的主键来确定。
4. **Delete object(s):** Can be used to delete an existing object whose primary key is derived from object reference parameters. This cannot reference an object created as a part of the current action.  
	删除对象：可以用于删除那些主键来自当前对象引用参数的现有对象。但是，无法删除在当前操作过程中创建的对象。
5. **Create link(s):** Can be used to create a many-to-many link between objects that are passed via object reference parameters. For foreign key links, one has to use **Modify object** rule to explicitly modify the foreign key property.  
	创建链接：可以用来在通过对象引用参数传递的对象之间建立多对多链接。对于外键链接，需要使用“修改对象规则”功能来显式地修改外键属性。
6. **Delete link:** Can be used to delete a many-to-many link between objects that are passed via object reference parameters. For foreign key links, one has to use **Modify object** rule to explicitly modify the foreign key property.  
	删除链接：可以用于删除通过对象引用参数传递的对象之间的多对多链接。对于外键链接，则需要使用“修改对象规则”功能来显式地修改外键属性。
7. **Function rule:** Can be used to reference an Ontology edit function whose inputs are derived from parameters of the action. When this rule is present, no other rule may be configured since function code alone is capable of handling everything that other rules can do. Read more about [function action types](https://www.palantir.com/docs/foundry/action-types/function-actions-overview/).  
	功能规则：可用于引用某个本体编辑函数，该函数的输入参数来自该动作的参数。当存在此规则时，无需配置其他规则，因为仅通过函数代码就能实现其他规则所能做的一切操作。更多关于函数动作类型的信息请阅读相关文档。
8. **Create object(s) of interface:** Can be used to create objects of any type that implements a particular interface. Read more about [actions on interfaces](https://www.palantir.com/docs/foundry/action-types/actions-on-interfaces/).  
	创建接口对象：可以创建实现特定接口的任何类型的对象。更多关于对接口的操作的信息请参考相关文档。
9. **Modify object(s) of interface:** Can be used to modify objects of types that implement a particular interface. Read more about [actions on interfaces](https://www.palantir.com/docs/foundry/action-types/actions-on-interfaces/).  
	修改接口中的对象：可以用来修改实现了特定接口的类型所对应的对象。更多关于对接口进行操作的信息请参考相关文档。
10. **Delete object(s) of interface:** Can be used to delete objects of types that implement a particular interface. Read more about [actions on interfaces](https://www.palantir.com/docs/foundry/action-types/actions-on-interfaces/).  
	删除接口中的对象：可以用于删除实现了特定接口的类型所对应的对象。更多关于对接口的操作信息请参考相关说明。
11. **Create link(s) on object(s) of interface:** Can be used to create links between objects of types that implement a particular interface. Read more about [actions on interfaces](https://www.palantir.com/docs/foundry/action-types/actions-on-interfaces/).  
	在接口中的对象上创建链接：可以用于在实现了特定接口的对象之间建立链接。更多关于接口上的操作信息请参考相关文档。
12. **Delete link(s) on object(s) of interface:** Can be used to delete links between objects of types that implement a particular interface. Read more about [actions on interfaces](https://www.palantir.com/docs/foundry/action-types/actions-on-interfaces/).  
	删除接口中对象的链接：可以用于删除实现了特定接口类型的对象之间的链接。更多关于接口上的操作信息请阅读相关说明。

### Values and parameters 价值观和参数

When creating or modifying links and objects, the Rules require additional values for their operation. When modifying an object, the rules also define which properties are modified. Each property in return is mapped to a value provided by one of multiple options (Rules on links can only take object reference parameters):  
在创建或修改链接和对象时，规则会为这些操作提供额外的参数值。在修改对象时，规则还会指定哪些属性会被修改。而每个属性则对应着一个由多个选项之一提供的值（链接相关的规则只能接受对象引用参数作为参数）。

- **From parameter:** An existing parameter of the same type as the property. By default, every new property being added to the rule will automatically create a parameter with the same name and will be mapped to take the value of this parameter.  
	从参数栏中：这是一个与属性类型相同的现有参数。默认情况下，每当向规则中添加一个新的属性时，都会自动创建一个同名参数，并且该属性的值将被映射到该参数的取值上。
- **Object parameter property:** A property of an existing object reference parameter. The property type of the object parameter needs to match the property type it is mapped to.  
	对象参数属性：这是现有对象引用参数中的一个属性。对象参数的属性类型需要与它所映射到的属性类型相匹配。
- **Static value:** A static value that only exists in the Rules part of the action type. This value is cannot be changed when interacting with the action in Workshop, Slate, or Object Views.  
	静态值：这种值仅存在于动作类型的“规则”部分中。在 Workshop、Slate 或对象视图中操作该动作时，无法更改这个静态值。
- **Current User/Time:** String and timestamp properties can also take on contextual values in the form of the actions current user or the time of submission. Just like the **Static value**, these values cannot be interacted with when submitting the action and cannot be used in other parts of the action type.  
	当前用户/时间：字符串和时间戳属性也可以包含上下文相关的值，比如当前用户执行的动作或提交的时间。与静态值类似，这些值在触发动作时无法被修改，也无法在动作的其他部分中使用。

### Creating an object & many-to-many link创建了一个对象，并建立了多对多关联。

You can also create objects and linked many-to-many at the same time. While just creating a many-to-many link requires objects on both sides of the link to exist prior, you can create both entities via one action type. Start by configuring a **Create object** rule with an object type that has a many-to-many link. Then click the **Add link** button below **Add property** to select the link type and configure the links.  
您还可以同时创建对象以及多对多的关联。虽然创建多对多关联需要先确保关联双方的对象都存在，但可以通过一个操作类型来同时创建这两个实体。首先，配置一个包含多对多关联的对象类型的创建规则。然后，在“添加属性”下方点击“添加关联”按钮，选择关联类型并配置关联关系。

In order to create a one-to-many or one-to-one link type, simply edit the foreign key on the object.  
要创建一种一对多或一对一的关联类型，只需编辑对象的外键即可。

### Invalid combinations 无效的组合

Action types can include combinations of Ontology rules. When multiple rules are defined, the actions backend compiles rules to generate a single edit per object (e.g., **Add object**, **Modify object(s)**, or **Delete object(s)**). For example, if the result of one rule updates a property to "A", but another rule in the same action type updates the same object's property to "B", the resulting edit would just update the property to "B". The order of rules affects the final object edit. As a result, the following combinations of object edits are not supported:  
操作类型可以包括多个本体规则的组合。当定义了多个规则时，操作后端会将这些规则整合起来，为同一个对象生成单一的编辑操作（例如，添加对象、修改对象或删除对象）。例如，如果某个规则将对象的属性更新为“A”，而同一操作类型中的另一个规则将同一对象的属性更新为“B”，那么最终的操作只会将属性更新为“B”。规则的顺序会影响最终的对象编辑结果。因此，以下这种对象编辑组合是不被支持的：

- Objects cannot be deleted before they are added or modified.  
	在对象被添加或修改之前，是无法删除它们的。
- Objects cannot be modified before they are added.  
	在添加对象之前，是无法修改这些对象的。
- Objects cannot be created twice in one form submission.  
	对象不能通过同一表单提交的方式创建两次。

## Other rules 其他规则

There are two types of rules that trigger a [side effect](https://www.palantir.com/docs/foundry/action-types/side-effects-overview/):  
有两种规则会引发副作用：

- [**Notification**](https://www.palantir.com/docs/foundry/action-types/notifications/) rules can be used to send a notification about the action. Parameters may be used to customize the content of the notification and the recipients. End users may adjust their preferences to receive notifications via in-platform push notification, email, or both. Notifications are sent once all action edits have been applied, however the content of the notification will be generated based on the state of the Ontology before edits are applied.  
	通知规则可用于发送关于该操作的通知。可以通过参数来定制通知的内容以及接收者的信息。最终用户可以调整他们的偏好设置，选择通过平台推送通知、电子邮件等方式接收通知。在应用所有编辑操作之后会发送通知，不过通知的内容将基于编辑前的 Ontology 状态来生成。
- [**Webhooks**](https://www.palantir.com/docs/foundry/action-types/webhooks/) enable an action to make a request to an external system when the action is applied. Action parameters can be passed into the webhook, which can in turn pass parameters through to the external request. Webhooks may be configured to run before or after edits are applied.  
	Web 钩子允许在某个操作执行后向外部系统发送请求。操作参数可以传递给 Web 钩子，然后由 Web 钩子将参数传递给外部系统。同时，Web 钩子也可以被设置为在编辑操作之前或之后触发。

There is an additional advanced rule that triggers a [build](https://www.palantir.com/docs/foundry/data-integration/builds/):  
还有一个额外的高级规则，它会触发构建过程的执行：

- [**Schedule**](https://www.palantir.com/docs/foundry/action-types/trigger-schedule-build/) rules can be used to trigger the build of a schedule. Action parameters can be passed into the schedule, which can in turn pass parameters to the underlying [parameterized transforms](https://www.palantir.com/docs/foundry/building-pipelines/parameterization/) inside the build. Foundry applies Ontology edits after the build begins.  
	调度规则可以用于触发调度的执行。可以在调度中传递操作参数，这些参数可以进一步传递给调度中的参数化转换操作。在调度开始之后，Foundry 会执行 Ontology 的编辑操作。
